# 历史召回

你写当前正文时，如果遇到“角色明明受过某件旧事影响，但上下文只给了一句履历/摘要”的情况，用本 Skill 召回旧回合材料。

它不是资料考据流程，也不是让你翻档案。目标只有一个：**拿到足够写当前反应的旧事细节**。

## 什么时候用

用在这些情况：

- 角色履历写着“某次失约后不再信任玩家”，但你需要知道当时是怎样的失约。
- 当前角色要提到旧承诺、旧误会、旧物件、旧秘密、旧伤口、旧伏笔。
- 你准备写“她想起那天……”之类的承接，但不确定那天具体发生了什么。
- 你需要判断一个角色此刻的抗拒、亲近、愧疚或警惕是否有历史依据。

不用在这些情况：

- 最近几轮上下文已经足够。
- 只是普通寒暄、转场、状态描述。
- 你只是想找更多素材来扩写，但当前剧情并不依赖旧事细节。

## 先把问题拆成检索条件

不要直接写一整句自然语言去问。先从当前上下文里拆出下面几类线索。

### 1. 涉及实体

填你已经知道的实体 ref，格式必须是 `<type>:<localId>`。

常见例子：

- `character:沈璃`
- `item:碎玉簪`
- `location:青石镇客栈`

只填真正能帮助定位旧事的实体，不要把所有在场角色都塞进去。通常不要填主角，除非你要找的是主角的某次重大选择、承诺、身份暴露或伤害他人的事件。

不知道实体 ref 的内容不要硬猜，放到“标签”。

### 2. 事件类型

从这组里选 1-3 个最贴近的：

- `对话交流`
- `玩家选择`
- `冲突争执`
- `关系变化`
- `承诺亏欠`
- `秘密揭露`
- `发现线索`
- `物品变化`
- `状态变化`
- `场景变化`
- `战斗危险`
- `计划目标`
- `交易谈判`
- `亲密暧昧`
- `伏笔回收`

事件类型是粗筛，不要只靠它定位；最好和涉及实体、标签一起用。

### 3. 标签

标签写短词或短语。它们可以是：

- 旧承诺：`失约`、`救命之恩`、`婚约`
- 旧误会：`隐瞒`、`拒绝解释`、`被误认为背叛`
- 关键动作：`退回碎玉簪`、`把门关上`、`没有回头`
- 非实体概念：`旧案`、`血脉秘密`、`不信任`
- 你想找的长一点的摘要短语：`把碎玉簪推回桌上`

短标签和较长短语都可以。越具体越好。

### 4. 时间线索

可选。只有上下文里有明确时间词时再填，比如：

- `翌日清晨`
- `三年前雨夜`
- `山门冲突时`

没有就不填，不要发明。

## 调用方式

调用 `run_script` 执行 `recall_turns` action。只传你拆出来的条件，不要传搜索数量、时间模式或其它策略。

```json
{
  "涉及实体": ["character:沈璃", "item:碎玉簪"],
  "事件类型": ["冲突争执", "关系变化", "承诺亏欠"],
  "标签": ["失约", "拒绝接受解释", "把碎玉簪推回桌上"],
  "时间线索": "翌日清晨"
}
```

条件不必全填；但至少给一个有效线索。只有一个很宽泛的线索时，结果可能会提示你补充条件。

## 看结果时怎么用

结果通常会给少量候选，每条有：

- `摘要`：旧回合发生了什么。
- `matched`：为什么命中。
- `excerpt`：当时正文的一小段摘录。
- `score`：匹配强度。

使用规则：

- 优先使用 `matched` 更精确、同时命中实体+标签+摘要短语的结果。
- 多个结果都像时，选更贴合当前角色和当前关系的一条；不要把所有旧事都塞进正文。
- 只把旧事细节融进当前人物反应，不要写“我检索到”“资料显示”。
- 找不到时不要编造精确旧对白、旧动作。可以只写抽象影响，例如“那次失约仍横在她心里”。
- 召回结果和当前 entity 状态冲突时：当前 entity 是状态权威，旧 turn 是历史证据。写作时保留“发生过旧事”，但当前状态以 entity 为准。

      "type": "object",
