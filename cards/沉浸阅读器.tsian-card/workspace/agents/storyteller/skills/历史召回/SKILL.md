# 历史召回

当当前写作需要很久以前的旧事件细节，而当前上下文/人物履历只给了简述时，使用本 Skill。它读取每个正式 turn 的 `meta.recall` 做初筛和打分，只返回少量候选摘要与短摘录，不要求你浏览 turn 文件。

## 何时使用

- 人物履历、关系、目标或创伤提到旧事件，但你缺少当时具体动作、物件、承诺、冲突或语气。
- 当前剧情要呼应旧承诺、旧误会、旧物件、旧线索、秘密揭露、伏笔回收。
- 需要确认“以前发生过什么”，避免凭空补旧对白或旧细节。

不用于普通近因回顾：如果当前上下文已经足够，不要召回。

## 查询写法

调用 `run_script` 执行 `recall_turns` action。只传半结构化条件，不要传 `limit`、`timeMode`、搜索策略等参数；脚本内部会控制候选上限与最近优先。

```json
{
  "涉及实体": ["character:沈璃", "item:碎玉簪"],
  "事件类型": ["关系变化", "承诺亏欠"],
  "标签": ["失约", "拒绝接受解释", "把碎玉簪推回桌上"],
  "时间线索": "翌日清晨"
}
```

字段纪律：

- `涉及实体`：只填已知实体 ref，形如 `character:沈璃`、`item:碎玉簪`。不知道实体 id 的线索放进 `标签`，不要硬猜 ref。
- `事件类型`：只能用这些枚举：`对话交流`、`玩家选择`、`冲突争执`、`关系变化`、`承诺亏欠`、`秘密揭露`、`发现线索`、`物品变化`、`状态变化`、`场景变化`、`战斗危险`、`计划目标`、`交易谈判`、`亲密暧昧`、`伏笔回收`。
- `标签`：写短词/短语/关键动作/误会/物件名/承诺内容；未知非实体概念都放这里。
- `时间线索`：可选，写剧情时间词，如“翌日清晨”“三年前雨夜”。

## 使用结果

- 结果里的 `摘要`、`matched`、`excerpt` 是旧情材料；把它自然融入正文，不要向玩家暴露检索过程。
- 多个候选冲突时，以 `score` 高、`matched` 更精确、实体+标签组合更多的结果为准。
- 找不到或结果提示条件过宽时，不要编造精确旧对白/动作；保守写“她记得那次失约”等抽象影响，或补充实体/标签后再召回。

    "inputSchema": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "涉及实体": {
          "type": "array",
          "items": { "type": "string" },

        "事件类型": {
          "type": "array",
          "items": {
            "type": "string",
