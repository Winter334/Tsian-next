# 属性刻度与估值

本文是卡脚本维护者的参考。世界架构师只定义维度、含义和力量参照；场记按 `回合后维护/SKILL.md` 的指导进行角色估值，`maintenance-core.js` 完成补齐与换算。不要让 Agent 手工套公式或预建实体库。

## 属性不是原著精确报数

属性是本局玩法采用的合理数值估计，支撑掷骰等规则；不是断言原作精确给出了角色数字。小说没有报数不妨碍使用共同基准，但估计不能反过来编造角色的客观境界、前史或隐藏能力。

相对评价 `ratings` 的普通参照为 **5**：

| 相对评价 | 语义参照 |
| --- | --- |
| 0 | 对应能力确实完全丧失，需要明确依据 |
| 1–3 | 明确缺陷或能力明显不足 |
| 4–6 | 普通范围；没有特别描写默认 5 |
| 7–9 | 相关训练、职业或稳定表现支持的优秀 |
| 10–12 | 有依据的罕见突出 |
| 13–15 | 有明确依据的极端天赋/表现 |

优先使用整数。不为人物“各有特色”而随机填数，不因主角/配角/反派身份加减数值；缺少描写不等于能力差。职业、年龄、训练和表现只影响真正相关的维度。

## 世界定义与确定性换算

维度数量为 4–8，名称匹配作品，`meaning` 说明其含义和普通参照；至少一个 growth 和两个 talent。维度名/数量在开局适配后保持稳定，以免已有属性和装备键失配。

- `growth` 随力量阶梯明显成长。
- `hybrid` 同时受先天与后天影响，增长较温和。
- `talent` 不随境界缩放。

`power.tiers` 是本世界明确的阶梯序列，应包括普通角色可用的参照；gentle/moderate/steep 对应最高与最低阶起点倍率 4/30/1000。程序计算相邻阶倍率 q。若阶梯数不超过 1，q=1。

`level.current/total` 描述已知阶内等级，转换为 `(current-1)/(total-1)` 的位置；没有细分等级时取该阶起点。令 position 为从 0 起的阶梯下标加阶内位置，初始数值为：

- growth：`round(rating × q^position)`。
- hybrid：`round(rating × q^(position/2))`。
- talent：`round(rating)`。

没有力量阶梯的世界 `power.tiers=[]`，换算倍率为 1；各维按共同参照估值，不伪造境界。有阶梯而缺少换算所需 tier 时，程序要求场记根据已知境界或身份/表现明确估档，**不能默认为最低阶**。没有特殊线索的普通角色可由场记明确选择普通档位。

因此，“默认 5”只指相对评价，不是所有境界的最终属性都等于 5。架构师不填写人物属性，场记不手工计算倍率。

## 补齐、保存与变化

- 创建人物时补齐所有已定义维度，遗漏评价默认 5；普通维护触及已有角色时只补缺项，不批量迁移或重估全部存档。
- 已有数值（包括合法的 0）保留。重复提交相同评价/境界/等级不重置训练变化，也不重复计入装备。
- 有新依据修订某个 ratings 时只更新相应维度；有境界/等级变化时才调整相应成长/混合维。已有评价基准的角色按新旧投影差额更新，保留已经生效的永久增减；没有相对评价但有既存数值的角色不凭空重置为基准。
- 普通永久增减仍由 equipment.refresh 的 attributeChanges 应用。属性变化后由装备核心重算装备贡献，保持安全整数与持有关系约束。
- 转入另一阶时，不自动沿用旧阶的阶内等级。
- 内部 powerTier/powerLevel/ratings 是玩法估值；已知完整境界写 identity.realm（如“武徒八重”），程序不以简化估档覆盖此文字。
- 临时伤病、疲惫和情绪优先记录为状态；不要自动永久降低所有基础维度。长期能力缺损只影响对应能力，不连带降低悟性、气运等无关维度。
- 不能根据一次掷骰成功/失败反向重估角色能力。本文不重构掷骰公式，数值平衡与叙事效果仍由实际玩法测试调整。
