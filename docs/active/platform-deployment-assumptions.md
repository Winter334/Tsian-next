# Tsian Platform Deployment Assumptions

## 1. 文档目的

记录平台部署模型带来的设计假设，避免每个任务重复纠结同一个问题。这些假设是"已确认事实"，不是待讨论的方向。

## 2. 部署模型

Tsian 平台是**官方统一部署**的。所有玩家通过**同一个域名**访问平台游玩，只是加载的内容（游戏卡）不同。

## 3. 网络可用性假设（关键）

**平台运行需要网络。离线是伪需求。**

- 玩家访问平台本身就需要网络（加载平台 shell、连接 AI provider 跑 Agent 回合）。
- 因此平台内任何能力都可以依赖网络：CDN 加载资源、bare import 解析、运行时获取依赖等。
- **不要**以"离线可用"为由增加设计复杂度：内嵌本可用 CDN 的库、做本地 fallback、缓存本可按需取的资源。
- IndexedDB 缓存的目的是**性能**（避免重复加载大型 wasm / 资源），不是离线生存。

历史教训：多个任务曾默认"需离线可用"而引入内嵌/本地兜底复杂度，最后都因网络本就必需而成为多余包袱。记录此处以防再犯。

## 4. 适用范围

- 平台 shell（`apps/platform-web`）的能力设计：构建服务、依赖解析、资源加载都可走 CDN。
- 游戏卡内容（Agent/Skill/前端源码）本身是本地的（玩家导入后存 IndexedDB），但**平台处理这些内容时可用网络**（如构建前端时从 CDN 解析框架 bare import）。
- AI provider 连接、模型调用：本就需网络。

## 5. 不适用

- 玩家的存档数据、游戏卡内容：本地持久化（IndexedDB），不依赖网络存储。
- 这些是"内容"，与"平台能力"区分。
