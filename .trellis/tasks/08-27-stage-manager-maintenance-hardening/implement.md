# 实施计划：场记回合后维护稳定性优化

## 改动顺序

1. 收束场记的常驻指令与正式入口。
   - 修改 `workspace/agents/stage-manager/agent.json`，移除常驻 schema/世界建模参考，并调整场记可见的工具清单。
   - 精简 `workspace/agents/stage-manager/AGENT.md` 为职责、不变量与 Skill 路由。
   - 检查 post-turn 调用点，保证它只传目标回合并要求先加载 `回合后维护` Skill；不修改无证据支撑的前端同步门禁。

2. 重写 `workspace/agents/stage-manager/skills/回合后维护/SKILL.md`。
   - 写入固定的读取、事实判定、实体查询、按需参考、目标微批次写入、结果消费、memory/recall 收尾步骤。
   - 加入渐进实体规则、`attributes` 派生边界、一次性龙套排除规则，以及一次局部重试/停止报告规则。
   - 把已知文件的原生读取和字段/schema/源文的定向读取写清楚，避免全量参考注入。

3. 用实体导航工具替代大聚合上下文。
   - 新增 `query_entities`：实现受限筛选、紧凑候选索引、命中理由、无匹配与读取失败区分，以及结果上限。
   - 新增 `read_entities`：实现 refs/字段选择、受限关系展开、深度/数量上限、缺失/读取错误/截断报告。
   - 从场记的日常流程和工具列表中移除 `read_maintenance_context`；先搜索其他调用方，再决定其保留兼容或删除，避免破坏未知使用者。

4. 改造结构化编辑的微批次与结果契约。
   - 更新 `workspace/tools/json_edit`，兼容 `{ target, ops }` 的自然形式和旧形式。
   - 按 target 分组，在单个 target 快照中预演和验证；同 target 任一操作失败时不写该 target 的部分字段，其他 target 继续执行。
   - 返回每项 `applied`、`noop`、`failed` 或 `not_run`，补充 target、索引、错误码、可重试标记和最小纠正信息。
   - 保留基础设施错误的异常路径；不要把普通操作失败升级为整个调用抛错，也不要引入跨文件回滚。
   - 仅在 `records.md` / `seeds.md` 的既有专用维护路径上，为 `text_edit` 对齐逐项结果和轻量结构校验；不重做通用 Markdown 编辑工具。

5. 对齐 recall 与最终摘要规则。
   - 保持 `commit_turn_recall` 在 Skill 的最后一步，核对它的失败输出能被 Skill 清楚消费。
   - 不增加 `maintenanceId` 或前端完成标记；必要目标失败时要求场记返回“部分维护完成”和未完成项，不能只写“维护完成”。

6. 做低成本验证与打包检查。
   - 为新增/改造工具补充小型确定性烟测：筛选和数量边界、读取展开/截断、自然批量格式、同 target 无半写、跨 target 继续执行和结果完整性。
   - 人工复核 Skill 与一份真实请求抽样，重点检查：非事实不落档、未知不补猜、实体创建取舍、失败后只重试失败目标。
   - 运行卡前端/工具可用的构建检查和现有游戏卡打包命令，检查产物包含卡内 Agent、Skill 和工具改动，且未触碰平台模板或将 `save/` 打进产物。

## 评审检查点

- `query_entities` 与 `read_entities` 必须比原生读取更擅长“定位实体”和“按关系展开”，不能变成另一种全库上下文注入。
- `json_edit` 的改造必须确实减少场记常见维护的协议/定位错误；若某段编辑能力与原生 `edit` 没有差异，不新增抽象。
- 每一次工具结果都能告诉 Agent 哪些目标已完成、哪些需要局部修正，避免它因一个小错误重放整个批次。
- 静态测试只覆盖脚本契约，不声称验证 LLM 对剧情事实的判断能力。

## 回退点

- 工具接口新增字段保持向后兼容；如新查询/读取工具发现调用问题，可恢复场记旧工具可见性，但不恢复全量 schema 常驻注入。
- `json_edit` 的微批次改动先用现有调用形态和自然形态进行烟测；若结果契约不兼容，优先扩展输出兼容层，不回退到“前序操作默默落盘、后续失败”的行为。
- 所有变更都局限于游戏卡目录，可通过回退相应卡内文件恢复，不影响停止维护的平台模板。
