# Trace JSON 折叠阅读优化

## Goal

让系统监视器中的 AI 请求 JSON 像 IDE 调试器一样能够按结构浏览和折叠，减少长消息、工具定义和 Provider 参数造成的纵向噪音，使开发者能快速定位需要查看的节点，同时保留完整诊断内容。

## Background

- 当前 `DiagnosticTracePanel.vue` 将请求拆为“参数 / 消息 / Headers / Provider 请求体”等多个区域，再交给 `JsonBlock.vue` 通过 `JSON.stringify` 渲染为静态 `<pre>`。
- 现有分区没有节点级折叠、结构摘要或长字符串收纳能力；数据量较大时，用户仍需要滚动浏览整段 JSON。
- 本任务是展示层优化，不改变统一 Trace 的存储、查询、导出或诊断契约。

## Requirements

1. AI 请求详情使用一个统一的 JSON 树展示 endpoint、streaming、parameters、messages、tools、headers 和 Provider body，不再显示多个独立 JSON 文本块，也不再用单独的“工具声明”区域重复请求数据。
2. 对象和数组节点均可独立展开或折叠；默认展开根节点和第一层容器，更深层节点默认折叠。
3. 折叠节点显示类型与规模摘要，例如 `{…} 8 项`、`[…] 24 项`；空对象和空数组应能直接识别。
4. 键名、字符串、数字、布尔值和 `null` 使用可区分的语法色；层级通过缩进和引导线表达，展开按钮具备明确的可点击与键盘操作语义。
5. 长字符串默认显示有限预览，并可在当前节点展开/收起；多行字符串展开后保持可读换行，不能因为单条消息撑满整个详情页。
6. JSON 树提供“全部展开 / 全部折叠 / 自动换行 / 复制 JSON”基础操作。复制内容必须是完整原始值，而不是当前折叠后的可见文本。
7. 响应正文继续以适合阅读自然语言的文本形式呈现；Provider Payload、工具调用和错误详情等结构化值复用同一个 JSON 树展示组件。
8. 保留现有 Trace 概览、筛选、状态、Usage、重试、错误摘要、原始记录和诊断包行为。

## Acceptance Criteria

- [x] AC1：打开 AI Trace 后，请求区只显示一个完整 JSON 树，原有“参数 / 消息 / Headers / Provider 请求体 / 工具声明”分块不再分别占据页面。
- [x] AC2：对象和数组可逐节点展开、折叠，初始状态下根节点与第一层容器展开，更深层容器折叠，并显示字段数或元素数摘要。
- [x] AC3：不同 JSON 值类型有稳定的视觉区分；嵌套层级、空容器和长字符串均能清楚识别。
- [x] AC4：长字符串可独立展开与收起；全部展开、全部折叠、自动换行和复制完整 JSON 均可用。
- [x] AC5：Provider Payload、工具调用和结构化错误详情采用同一树形交互；自然语言响应正文仍保持直接可读。
- [x] AC6：统一 Trace 的存储结构、contracts、查询、导出和 workspace 投影不发生变化。
- [x] AC7：`npm run build:web` 通过；浏览器交互与视觉效果由用户手动验收。

## Out of Scope

- JSON 内容搜索、路径复制、节点值单独复制、编辑能力和超大 JSON 虚拟滚动。
- Trace 数据模型、持久化、脱敏、诊断包和旧 Trace 兼容策略调整。
- 自动化浏览器测试、全量测试和额外的重型 review/check 流程。

## Delivery Constraints

- 按轻量 UI 任务执行，仅做与改动风险相称的代码检查和 `build:web`。
- 不启动浏览器测试；实现完成后提供简短的手动验收清单，由用户验收。
- 优先在现有 Vue/Tailwind 技术栈内实现，不为本功能引入重量级 JSON Viewer 依赖。
