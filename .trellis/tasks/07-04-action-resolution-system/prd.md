# 行动裁定玩法系统

## Goal

设计并实现“行动裁定”作为默认 AIRP 的首个真正玩法系统，整合随机判定、数值修正、双方对抗、脚本运算与结果维护。它是会影响剧情结果的玩法系统，不是前端渲染结构。

## Requirements

- R1: `mode.json` 中以 `"行动裁定": "enabled" | "disabled" | "deferred"` 表示该玩法状态。
- R2: 行动裁定整合随机判定和数值系统，不硬拆成“投骰系统”和“数值系统”两个 mode 项。
- R3: 说书人只在行动裁定为 `enabled` 且玩家行动存在不确定性、风险、对抗或代价时使用该玩法。
- R4: Agent 不直接手算骰子、表达式、DC 对比或双方数值对抗；确定性/随机运算通过脚本完成。
- R5: 行动裁定脚本支持第一版最小能力：投骰、表达式计算、难度检定、带修正检定、对抗检定。
- R6: 修正来源可以来自角色/实体字段、状态、extensions 或规则文件；读取和解释方式由对应 Agent-local Skill 指导。
- R7: 裁定结果应结构化返回给说书人，便于写入剧情；也应可被场记读取/接收，用于维护 runtime/entity/status/extensions。
- R8: 世界架构师的行动裁定 Skill 负责启用时初始化基础 rules/schema 示例。
- R9: 场记的行动裁定 Skill 负责把结果落盘，不让说书人维护状态。
- R10: 未启用时说书人不偷偷投骰、不硬算；`disabled` 时后台不主动建议；`deferred` 时可由场记/世界架构师在明显需要时提出轻量建议。

## Acceptance Criteria

- [ ] 存在行动裁定的 Agent-local Skill 设计：说书人、场记、世界架构师各自视角不同。
- [ ] 存在可调用脚本或 helper，完成骰子/计算/检定/对抗等最小能力。
- [ ] 行动裁定结果结构化，能被说书人用于正文、被场记用于维护。
- [ ] 启用行动裁定时能生成基础 rules/schema/runtime 示例，且符合中英混用约定。
- [ ] 未启用时默认剧情仍可纯叙事运行。
- [ ] 不把人物卡、背包、状态栏等 UI 模块混入行动裁定玩法。
- [ ] 必要构建/测试通过。

## Notes

行动裁定是第一版真正玩法系统。它的实现应保持可扩展，但不要一开始设计成完整 TRPG 规则引擎；先满足轻量判定、修正和对抗，再根据剧情和后续 Skill 扩展。
