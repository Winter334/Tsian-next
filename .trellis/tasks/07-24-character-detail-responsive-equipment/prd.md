# 角色详情响应式重设计与装备展示

## Goal

重新设计正式游戏前端的角色详情页，让角色立绘成为“角色 / 物品”两种模式共享且稳定的视觉焦点，提升属性、装备与容器信息的空间利用率，并为正式游戏建立可延续到其他页面的最小移动端壳层。

第一版以只读浏览和响应式体验为目标：接入新增装备 Schema，重组角色详情信息架构，验证桌面与移动端的布局和交互；换装等写入能力留待后续扩展。

## Background

- 当前角色页由人物列表、独立立绘列和“概况 / 属性 / 背包”详情列组成，立绘下方及属性、背包内容区存在明显空旷：
  - `apps/play-frontend-dev/src/components/character/CharacterView.vue:115-216`
  - `apps/play-frontend-dev/src/components/character/CharacterCard.vue:92-151`
  - `apps/play-frontend-dev/src/components/character/CharacterDetail.vue:45-99`
- 当前角色主路径和正式游戏壳层没有完整的窄屏布局切换，固定人物栏、左右侧栏和详情列会继续占据横向空间：
  - `apps/play-frontend-dev/src/App.vue`
  - `apps/play-frontend-dev/src/components/AppHeader.vue`
  - `apps/play-frontend-dev/src/components/AppNav.vue`
  - `apps/play-frontend-dev/src/components/StatusBar.vue`
  - `apps/play-frontend-dev/src/components/character/CharacterView.vue:168-216`
- 装备契约已定义动态角色槽位、装备物品字段和实际属性贡献，但开发前端类型与解析器尚未保留这些字段：
  - `cards/沉浸阅读器.tsian-card/workspace/docs/novel-airp-schema-reference.md:96-163`
  - `apps/play-frontend-dev/src/lib/character-types.ts:106-143`
  - `apps/play-frontend-dev/src/lib/parse-character.ts:233-291`
  - `apps/play-frontend-dev/src/lib/item-types.ts:51-60`
  - `apps/play-frontend-dev/src/lib/parse-item.ts:144-169`
- `character.attributes` 是包含装备结算结果的当前有效值；装备贡献说明以槽位中的 `applied` 为准。
- 装备槽名称来自角色数据，不能硬编码通用人体部位或自动补槽；展示顺序必须保持源对象键顺序。
- 已装备物品仍位于角色可达的容器图中，UI 不得表现为物品已从背包移出或进入虚拟装备容器。

## Requirements

### R1. 一级信息架构与状态

- 将“概况 / 属性 / 背包”重组为页面顶部控制条中的两个一级模式：
  - **角色**：角色资料、动态属性、特殊量表、状态、特质、关系、目标、履历和可展示扩展信息。
  - **物品**：动态装备槽、容器浏览和物品详情入口。
- 立绘不属于任一模式；切换模式时保持同一立绘实例和稳定视觉位置，只替换周围及后续的信息层。
- 切换角色时保留当前“角色 / 物品”模式，不强制回到角色模式。
- 双轨滚动位置按模式分别保留，切回模式时恢复该模式先前的位置。
- 第一版允许后续继续调整比例和装饰，但不得再把属性、装备或背包拆回空间利用率不足的独立大标签页。

### R2. 角色舞台与立绘

- 桌面和移动端都以无框立绘为舞台中心，不恢复独立、与内容割裂的立绘列。
- 舞台立绘使用静态、克制的“烟墨消散”不规则边缘；效果不应依赖持续动画，也不得影响图像点击和可读性。
- 舞台只在显示层裁切图像，不能以展示比例反向限制已保存原图。
- 姓名、身份和特殊量表与立绘建立明确联系；特殊量表放在立绘下缘，并与普通属性保持语义区分。
- 缺少立绘或角色可选字段时沿用现有默认头像与容错空态，不导致页面失败。

### R3. 角色模式

- 动态属性改为围绕立绘的双侧紧凑轨道，不再占用独立标签页。
- 单个属性使用无完整边框的方形属性印记：名称位于左上，数值位于左下，内部由右上向左下的真实 UI 对角线分区，不使用文本 `/` 字符模拟。
- 属性印记通过克制的底色、光晕或局部角标确认边界；hover/focus 只增强斜线、底色和文字，不出现厚重完整描边。
- 不硬编码属性集合；按 `attributes` 的动态键和原始顺序交替排入左右轨道。
- 人物资料主体在独立档案区域展示简介、状态、特质、关系、目标、履历和扩展信息；字段缺失时隐藏区块或显示合适空态。

### R4. 物品模式：装备舞台

- 使用接近传统 RPG 的双侧装备轨道，让紧凑槽位围绕立绘排列，但不把槽位映射到数据未声明的身体部位。
- 按 `character.equipment` 原始键顺序交替分布槽位，不自动补槽。
- 槽位采用“通用装备图标 + 动态槽位短签”的紧凑方形；完整槽位名进入 Tip 或详情层，长名称不得扩大槽位占位。
- 桌面悬停可显示轻量 Tip，至少包含完整槽位名、物品名和主要实际贡献；移动端点击直接打开完整详情，不增加 Tip 的二次点击路径。
- 已装备槽点击后打开统一物品详情；空槽保持可识别，但不出现换装按钮。
- 槽位不得常驻展示大段修正值、效果或物品描述，不得抢夺立绘视觉焦点。

### R5. 容器浏览

- 物品模式的主体空间优先用于容器浏览，不设置常驻物品详情栏。
- 容器与物品使用统一尺寸的方格网格；容器通过图标、纹理或进入提示与普通物品区分，而不是占用不同尺寸。
- 点击容器后在同一容器区域就地进入下一层，并通过面包屑返回；容器本身不打开详情模态框。
- 已装备物品仍显示在原容器中，并带有“已装备 / 槽位”状态；装备槽与当前可见容器中的同引用物品具有聚焦或选中联动。
- 容器递归浏览必须防止环；缺失、损坏或不可达引用以容错状态展示，不造成界面崩溃。

### R6. 单物品详情

- 普通物品和装备物品共用单物品详情模态框，不提供上一件/下一件导航，也不承担容器浏览。
- 装备物品详情在名称、类型、简介、标签和扩展信息基础上展示：
  - 建议槽位 `equipment.slot`；
  - 原始修正规则 `equipment.mods`；
  - 叙事效果 `equipment.effects`；
  - 当前角色中的已装备槽位；
  - 对应槽位记录的实际贡献 `applied`。
- 桌面使用居中卷宗式模态框；移动端使用接近全高的底部纸张/底部模态形态。
- 模态框支持遮罩、明确关闭按钮和 Escape，并具备焦点圈定、关闭后焦点恢复及内部滚动控制。

### R7. 立绘查看与更换

- 所有具有有效实体引用的角色都可点击舞台立绘打开立绘模态框，不再在立绘下方常驻“更换头像”按钮。
- 立绘模态框使用 `contain` 展示已保存的完整图像，并提供上传/替换入口；未来的立绘生成入口可在该模态框中扩展。
- 新上传图片继续校验 PNG/JPG/WebP 和 5MB 上限，解码后按原始宽高比缩放至最大边 1024，并导出 WebP；不得在写入前永久裁成舞台比例。
- 既有已裁切立绘继续兼容显示，不执行迁移或回填。

### R8. 第一版只读与钉选边界

- 第一版只展示装备、容器和物品状态，不允许装备、卸下、移动或拖放物品。
- 不实现 modifier 表达式求值、属性原子刷新、装备所有权变更或失败回滚。
- 界面不得出现会误导用户认为可立即换装的按钮或拖放暗示。
- 仅主角字段显示现有状态栏钉选入口；NPC 字段不提供钉选，避免现有按字段类型/键识别的钉选状态产生跨角色冲突。
- 除现有立绘更换外，本任务不新增角色数据写入。

### R9. 桌面布局与滚动所有权

- 人物选择改为约 156–176px 的精简常驻栏，每项只显示头像、姓名及轻量主角/当前项标记。
- 第一版人物栏仅显示当前场景 `scene.present`，不显示或虚构“关联人物”分组。
- 桌面端具有三个互不抢占的滚动域：人物栏、角色舞台信息层、右侧档案/容器区域。
- 舞台双轨由同一滚动位置驱动并同步移动；立绘、姓名/身份和立绘下缘量表保持锚定，不随双轨滚走。
- 所有滚动条视觉上隐藏；通过自然露出、边缘淡化或轻微遮罩提示仍有内容，不使用突兀的滚动条替代物。

### R10. 移动角色页

- 移动端不保留常驻人物栏；页面顶部控制条左侧使用当前角色头像按钮，右侧显示“角色 / 物品”切换。
- 点击头像按钮从左侧打开人物抽屉，不支持边缘滑动；抽屉只显示当前在场角色的头像和姓名，选择后自动关闭。
- 首屏以约 34–40dvh 的完整立绘作为 Hero；向下滚动越过 Hero 后，立绘收束为含小头像、姓名和身份的紧凑角色条，返回顶部时恢复完整立绘。
- 移动端属性或装备双轨折叠为立绘下方的两列内容，跟随角色页唯一主滚动，不创建嵌套的主内容滚动区。
- 控制条持续可达，紧凑角色条不能与全局 Header 争夺同一吸顶层级。
- 处理动态视口高度、安全区和底部导航占位；尊重 `prefers-reduced-motion`，减少动态时直接切换状态。

### R11. 最小全局移动壳层

- 手机布局下，`StatusBar` 不再以固定左栏或折叠 rail 占据横向空间，改由压缩后的 `AppHeader` 按钮打开状态抽屉。
- 手机布局下，`AppNav` 不再以固定右栏或折叠 rail 占据横向空间，改为处理底部安全区的底部主导航。
- 移动抽屉均通过按钮触发，并支持遮罩、明确关闭按钮、Escape、焦点圈定与关闭后焦点恢复。
- 故事、时间线和设置等页面本轮不重做内部内容，但应获得移动壳层提供的完整可用宽度。
- 桌面继续保留现有 Header、StatusBar 和 AppNav 的展开/折叠行为。

### R12. 响应式与发布边界

- 桌面与移动端复用同一数据和核心组件，通过布局重排切换人物栏/抽屉、双轨方向、容器网格和模态形态，不维护两套业务实现。
- 保持 Vite `base: "./"` 和 iframe 沙箱兼容，不依赖宿主页面 DOM 或 CSS。
- 本轮只修改和验证 `apps/play-frontend-dev` 开发前端；不更新 `cards/沉浸阅读器.tsian-card/frontend/src`、`frontend/dist` 或 `game-card.json.frontendFiles`。
- 正式卡可在后续通过导入最新前端包获得本轮内容，卡内前端快照同步不属于本次交付。

## Acceptance Criteria

- [ ] 页面只保留“角色 / 物品”两个一级模式；模式切换不重新挂载立绘，切换角色保留模式，双轨滚动位置按模式恢复。
- [ ] 角色模式按动态键顺序显示无框方形属性印记和真实 UI 对角线，不再存在独立属性标签页。
- [ ] 物品模式按源对象键顺序显示动态装备槽，不硬编码或自动补槽；槽位使用图标和短签。
- [ ] 角色和物品解析边界保留合法装备字段，忽略局部非法字段且不导致页面崩溃。
- [ ] 已装备物品同时可见于装备轨道和原容器，并显示槽位状态及同引用联动。
- [ ] 容器与物品使用统一方格；容器在原区域就地进入，面包屑可返回，循环/损坏引用有容错。
- [ ] 点击普通物品或已装备槽打开统一的单物品详情；装备建议、规则、效果与实际贡献可见。
- [ ] 第一版没有装备、卸下、移动、拖放或 modifier 求值操作。
- [ ] 仅主角字段提供钉选入口；NPC 字段不显示钉选。
- [ ] 所有有效角色的立绘可点击打开完整图像模态；新上传立绘保持原始宽高比保存，舞台裁切只发生在显示层。
- [ ] 桌面仅列出当前在场人物，并使用人物栏、舞台双轨和右侧内容三个独立滚动域；双轨同步滚动而立绘固定。
- [ ] 所有可滚区域隐藏滚动条，并以克制的边缘淡化或内容露出提示可滚动性。
- [ ] 移动端通过头像按钮打开在场人物抽屉，属性/装备双轨折叠为两列；角色页只有一个主内容滚动域。
- [ ] 移动首屏显示完整 Hero 立绘，滚动后显示紧凑角色条，返回顶部恢复；减少动态设置得到尊重。
- [ ] 手机布局下状态栏变为顶栏触发的抽屉，主导航变为安全区友好的底部导航，左右 rail 不占横向空间。
- [ ] 模态框和抽屉支持键盘关闭、焦点圈定、焦点恢复与可见焦点状态。
- [ ] 桌面壳层既有展开/折叠行为无回归；其他正式游戏页面在手机布局获得完整可用宽度。
- [ ] `apps/play-frontend-dev` 构建通过，桌面与移动视口手动验证通过；正式卡前端目录和清单未被本任务修改。

## Out of Scope

- 前端直接换装、卸装、拖放或移动物品。
- modifier 表达式求值器、装备属性刷新器和装备写盘事务。
- 装备物品独立图片上传或图片 Schema。
- 开局向导的移动端适配。
- 角色页之外正式游戏页面的内部内容和视觉重设计。
- 装备 Schema、Stage Manager、Storyteller 工具或存档权威 Schema 的额外改造。
- 正式卡内 packaged frontend 源码、构建产物及 `frontendFiles` 同步。
