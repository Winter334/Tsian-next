# 正文 Agent 原作文风学习

## Goal

让 Storyteller 在用户启用“原作文风”模块时，从当前导入小说的实际正文中提炼可执行的写作规则，并把规则写回该模块自身。学习完成后，现有文风宏直接注入学习结果，正文写作不再重复分析源文本。

这使导入长篇小说的玩法能够利用原作自身的表达规律，同时保留现有预设文风，供粘贴片段、短篇故事、源文本不足或用户偏好其他风格时手动选择。

## Background

- Storyteller 的现有文风入口是 `{{file:modules/文风/*.md?enabled}}`，用户负责启用文风模块。
- 现有模块是固定预设，不能反映当前导入小说的稳定文体特征。
- “原作文风”采用自举文件：初始内容是一次性学习指令，学习后由 Storyteller 用提取结果整体替换同一文件。
- 文风模块在产品约定上互斥，但启用状态完全由用户管理。系统不处理同时启用多个模块所造成的风格冲突。

## Requirements

### R1. 用户控制

- 保留所有现有预设文风模块及其手动开关行为。
- 新增“原作文风”模块，默认关闭。
- 系统不自动启用、禁用、组合或切换任何文风模块。

### R2. 自举学习

- “原作文风”文件的初始内容直接指导 Storyteller 执行一次文风学习，不新增传统 Skill。
- 用户启用该模块且文件仍为初始学习指令时，Storyteller 读取当前导入小说的实际正文，提取文风，并用结果整体替换同一固定文件。
- Storyteller 在完成写入后继续生成当前回合正文，并在当前回合使用刚提取的规则。
- 文件被替换为文风规则后，后续回合只消费规则，不持续或增量更新。
- 需要重新学习时，由用户恢复初始内容或直接编辑文件。

### R3. 来源边界

- 文风判断必须依据实际源小说正文，不依据章节摘要、时间线摘要或角色资料代替原文。
- 只读取当前已读范围内的源文本，不为学习文风而越过既有阅读进度。
- 当实际可读正文不足以形成稳定判断时，不伪造“原作文风”，也不覆盖初始文件。

### R4. 提取产物

- 产物是可直接影响正文决策的操作性写作规则，而不是文学评论、作者介绍或赏析。
- 规则应覆盖源文本中稳定且可复用的表达特征，例如叙述距离、句段节奏、信息组织、对白习惯、描写取舍、修辞密度与情绪表达。
- 产物不保留剧情事实、角色名、专有名词、原文引句或剧透信息。
- 固定文件是唯一权威副本，不生成额外文风文件。

### R5. 职责归属

- 文风读取、提取、写入和同回合应用均由 Storyteller 负责。
- World Architect 不参与文风提取，也不维护该文件。

### R6. 最小实现

- 允许调整 Storyteller 的工作区写入能力，使其能够改写固定的卡内容文件。
- 文风是用户可查看和修正的纯语义文本，不增加格式校验、写入恢复、自动修复或额外保护层。
- 不增加文风模块组合算法、优先级规则、互斥校验、冲突提示或自动开关逻辑。

## Acceptance Criteria

- [ ] “原作文风”作为默认关闭的文风模块随卡打包，并继续通过现有文风宏注入。
- [ ] 用户启用初始状态的“原作文风”后，Storyteller 能读取已读范围内的实际源正文，生成操作性文风规则，并整体覆盖同一文件。
- [ ] 覆盖后的文件在后续回合按普通文风模块使用，不再次触发学习。
- [ ] 学习发生的当前回合仍会继续输出正文，并应用刚生成的文风规则。
- [ ] 源正文不足时，Storyteller 不编造规则、不覆盖初始文件，并继续处理当前正文请求。
- [ ] 学习产物不包含剧情事实、角色名、专有名词、原文引句或剧透信息。
- [ ] Storyteller 在玩家正式回合和旁路调用两种运行路径中都能持久化该卡内容写入。
- [ ] 现有预设文风模块及用户手动开关行为不变。
- [ ] 实现不包含文风组合、优先级、强制互斥、自动切换、内容校验或恢复逻辑。

## Out of Scope

- 按导入类型、文本长度或其他条件自动启用文风学习。
- 自动选择最合适的预设文风。
- 同时启用多个文风模块时的合并、仲裁或防护。
- 持续、定期或按章节增量更新已学习的文风。
- 为不同存档或不同来源维护多份自动切换的原作文风。
- 重写现有预设文风模块的内容。
