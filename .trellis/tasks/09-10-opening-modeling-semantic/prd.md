# 世界架构师开局建模语义化

## 状态

2026-09-10：需求方向和职责链已确认，任务规划完成，尚未开始业务实现。没有阻塞性的产品待确认项；具体语义参数形状、脚本划分与实现细节按本任务原则收敛。

前置：[场记语义化改造](../09-10-stage-manager-semantic-maintenance/prd.md)已完成。用户实测效果良好，回合后维护约 1 分钟；这是用户反馈，不是开局性能的量化目标或受控基准。

## 目标与确认的职责链

**玩家访谈确认 → 架构师提交初始世界 → 正文 Agent 生成开局 → 场记按正文更新资料 → 开局就绪。**

- 世界架构师负责理解原文和玩家意图、定义世界概念并建立开局前的资料；不维护文件系统，不调度固定的后续 Agent，也不承担正文后的审稿/资料修补。
- 正文 Agent 消费已经提交的初始资料，生成开局正文。确保材料真正进入其输入；更广泛的正文消费质量和续写能力优化留待后续，不用架构师事后逐项对照 JSON 来补偿。
- 场记是正文后的专业维护者，开局也运行一次场记。扩展已实现的语义维护协议以支持开局回合，不另建一套开局维护模型。
- 固定流程由卡前端程序编排，不再由架构师 agent_call 写手和场记。语义上“是否已充分访谈并获得玩家确认”仍由架构师判断；程序以真实提交结果而非口头回复推进。

## 范围

### 1. 世界架构师的语义建模接口

- 将交付聚焦为两类内容：世界定义（概念、属性含义、力量规则、特殊机制及必要展示意图）和初始资料（人物、地点、物件、关系、当前局面、玩家切入点）。
- Agent 判断语义；程序分配标识、包装物理引用、生成文件/可渲染结构并执行确定性刻度计算。选档位、人物差异和剧情位置仍需语义判断，不能因字段为数值便机械化。
- 联动修改 AGENT/SOUL、Skill、脚本工具、卡内上下文材料及其生成点。不仅重命名原始 JSON 提交接口。
- 源文本取证能力优先复用；不要求架构师掌握分片路径、存档地图和关系文件布局。
- 沿用现有主要资料类别与展示能力，不建设万能 schema DSL。schema/规则变化留在卡可编辑层，不搬进平台注入器。

### 2. 固定流程的程序编排

- 访谈保留必要的对话连续性；区分访谈记忆与后台执行材料，消除“实际持久化但提示词声称每次清空”的矛盾。
- 卡前端分别调用架构师、写手和场记。初始资料提交成功后才能调用写手；正文保存成功后才能调用场记。
- 程序准备各 Agent 的任务材料，不让架构师维护路径清单、阶段进度、继续标记或转抄正文。
- 独立 invocation 不共用父调用的 staged workspace；需要明确持久提交边界。responseRef 不跨 invocation 复用，程序直接转交原始输出。
- 只有开局正文与场记维护均成功，才进入可开始正式游玩的状态。调整当前 publish_opening 立即标 complete 的完成边界。

### 3. 简化保护与恢复

- 重新评估并退出不再必要的实体→graph→state 模型侧阶段锁，不以修补旧锁的回退能力为目标。
- 保留真正有价值的保护：玩家确认、来源/当前开局身份一致、正式游玩后不被开局覆盖、失败不留下被误认为完成的半套资料、重复执行不重复创建。
- 正文失败不重新访谈/建世界，场记失败不重新生成正文。必要进度随存档保存，不只放在 Vue 内存；刷新恢复不静默重复产生 AI 调用。
- 开局回合与后续正式回合的编号、上下文、维护凭据和状态刷新必须连贯，避免重复 turn 0 或首个正式回合错位。

### 4. frontier 与 RAG 边界

- frontier 可能过度设计，用户明确允许本轮影响它；不为了保持旧 frontier 正常而保留架构师原生工具、复杂注入或开局时间线生成要求。
- 可解除开局对 frontier 的硬依赖，并配套停止受影响的旧自动调用；不通过空壳数据或兼容分支维持一条已失效流程。本轮不设计新的 frontier 替代系统。
- plotOrder 属于语义字段，但其所属功能不因此必须永久保留；与 frontier 的去留及直接消费者一起判断，不按机械计数处理。
- RAG 已废弃但暂时保留，后续重构增强。本轮不修改、不清理、不验证 RAG。

## 非目标

- 不让通用上下文注入器理解玩法 schema，不创建通用工作流引擎。
- 不恢复废弃平台模板；不同时维护卡内旧前端副本。
- 不建设旧卡/旧存档兼容或迁移框架，不自动批量覆盖已有玩家资料。
- 不全面重构正文 Agent，不新增架构师发布后的强制语义审稿轮次。
- 不调用真实/付费 AI 作为本地验收门槛，不承诺未经实测的开局耗时。

## 验收

- [ ] 正常开局中，架构师无需理解物理路径、分片、渲染包装、机械编号和阶段锁；语义输入经程序生成有效资料。
- [ ] canon/original 访谈与玩家确认保留，固定后续调用由卡程序发起，不依赖架构师 agent_call、路径笔记或继续标记。
- [ ] 写手调用使用已提交的初始事实材料，输入/职责不要求架构师再审查正文并修改初始资料。
- [ ] 开局正文保存后，由场记通过同一语义维护机制更新状态；维护未成功不得开放正式游玩。
- [ ] 开局回合与首个正式回合衔接正确；重试不重复正文、人物、关系、记忆或计数。
- [ ] 失败/刷新能恢复必要步骤，不误标成功、不覆盖已开始游玩的存档、不静默重复调用模型。
- [ ] Agent/Skill/脚本/上下文/卡前端与初始资产一致；真实打包导入验证通过，废弃来源不复活。
- [ ] 不为 frontier 设置兼容保留门槛；受影响的旧调用有明确处理，RAG 未纳入改造。

## 验证责任

本地使用必要的固定语义输入、脚本/引用与确定性计算测试、失败回滚/幂等测试、开局编排和 turn 0 衔接测试、上下文构造测试、相关构建与真实卡包验证。用户负责实际模型的提取/建模质量、正文消费质量、速度和体验测试；固定夹具不能被报告为 AI 质量验证。
