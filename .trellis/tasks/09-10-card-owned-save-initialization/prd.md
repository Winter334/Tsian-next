# 前置清理：卡内容来源与卡属存档初始化

## 关系与当前状态

本任务先于[场记语义变更协议与上下文转型](../09-10-stage-manager-semantic-maintenance/prd.md)交付。2026-09-10 已完成实现、相关测试、构建以及真实卡包导入/新建存档验证。任务目录暂保留，便于主任务追踪前置结果。

## 用户要求

目前卡内静态资料、卡前端源码、平台动态生成内容、已废弃内置模板混杂，容易改错副本或漏掉生产者。先清理这一现状，再实施场记转型。

不同卡拥有不同 schema，玩法相关的新存档结构/初始资料应随卡分发，不应由平台统一灌入小说 AIRP 模板。无相关配置的卡允许使用简单、通用的最小兜底。用户已认可“声明式配置 + 卡内初始文件树”为承载方式，不以初始化脚本作为必选入口；现已确认配置/复制/兜底及旧卡处理方向，具体合同见下文。

用户进一步确认：项目仍在测试阶段，只有沉浸阅读器一张官方卡，且即将更新该卡。保持最简单的逻辑，不建设旧卡兼容层、存档迁移框架或过渡期双轨初始化。此约束同时适用于后续场记转型。

## 目标

1. 确认实际生产源和发布链，区分权威源码、打包产物、已废弃能力副本、仍被使用的初始化代码与测试夹具。
2. 将卡特有初始存档与资料交还卡；平台只处理通用创建、路径/权限、存储、checkpoint 与必要内部元数据。
3. 确保打包、导入、存储和创建新存档消费同一初始数据合同，避免新字段在归一化/再导出时丢失。
4. 简化/退出废弃模板的生产依赖；先迁走仍被使用的逻辑，不以目录名为依据整目录删除。
5. 为后续场记新上下文材料与语义工具提供清楚的生成和分发位置。

## 范围

- 卡 manifest/contracts、静态初始存档资产、打包/导入/导出/安装存储、新建存档流程。
- `createDefaultSaveRuntimeFiles`、现有 workspace 版本补文件路径、内置空白卡及其实际依赖。
- 卡前端真实来源 `apps/play-frontend-dev/src` 与卡 workspace 的来源说明；清理确认无生产用途的副本/引用/测试依赖。
- 最小通用兜底的内容与触发条件、初始 checkpoint、非法配置和失败处理。
- 新配置对既有存档的明确边界。新存档初始化不等于既有存档迁移，不因导入新版卡覆盖玩家资料。

## 非目标

- 不在前置清理时实施场记语义协议转型。
- 不为所有卡制定玩法 schema、世界规则或全局 JSON Schema 引擎。
- 不因为支持初始化便默认增加任意脚本执行钩子。
- 不恢复旧 Agent/Skill 模板双份维护，不开展无关仓库重构。
- 不增加旧卡识别/特殊兜底、迁移版本链、自动补写业务文件或自动清理旧存档；旧卡缺配置按普通无配置卡处理。

## 验收方向

- [x] 两份最小测试卡夹具（不新增第二张产品卡）分别创建结构不同的存档，互不混入小说 AIRP 文件或对方资料。
- [x] 沉浸阅读器的新存档从随卡分发的初始资料启动，开局建模/正式回合必要文件齐全。
- [x] 无初始化配置的卡使用 schema 无关的最小兜底；没有角色阵容、世界观、frontier 或属性维度等隐含要求。
- [x] 已配置但非法/缺失的初始化资源明确报错，不静默回退掩盖坏包；声明目录无文件也报错，无初始业务文件的卡直接不声明配置。
- [x] 真实打包→导入→创建新存档→导出/再导入保留配置与文件；不要求卡访问平台本地源码。
- [x] 平台内置元数据与卡初始业务数据分离；路径越界、保留目录、重复/冲突文件受控；失败不留下半初始化存档/初始 checkpoint。
- [x] 打开既有存档不会被通用升级路径重新补入已移走的 AIRP 模板；不自动重置或覆盖现有玩家资料。
- [x] 形成准确的生产源/生成者/消费者/分发清单，修正本任务实际触及的陈旧知识。

## 已确认的实现合同

- 卡 manifest 使用 `runtime.initialSave: { templateRoot: "initial-save" }`；`templateRoot` 相对卡工作区根，不含磁盘上的 `workspace/`。目录名可由卡选择，只有显式声明才启用。
- 目录下文件按相对路径复制至新存档 `save/`，保持内容，不展开宏、不解释玩法字段，不与 AIRP 默认业务文件合并。
- 未声明配置：业务文件为空，仅创建平台必要记录、内部元数据和初始 checkpoint；不保证缺少卡私有数据的前端完整可用。
- 声明无效、资源缺失或目录无文件：明确报错；不添加显式空模板模式。
- 只在创建新存档时实例化一次；导入/更新卡包、打开/回溯存档不重新套用模板。
- 沉浸阅读器在本任务同步更新并重新打包。不保留旧卡隐式 AIRP 初始化，不做自动迁移。
- 既有玩家资料不自动覆盖或删除；取消通用版本升级对 AIRP 业务文件的补写。不额外建设兼容层，也不以“清理”为名销毁测试存档。
- 平台必要内部元数据与卡业务模板分离；实现时沿实际消费者确定最小集合，不引入新的玩法假设。
