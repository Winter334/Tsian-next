# Spatial 渲染与输入基础

## Goal

建立并验证 Spatial Desktop 的最小技术底座：真实 HTML 保持布局、语义、焦点与表单状态，经 HTML-in-Canvas 捕获后由 WebGL 形成浅圆柱曲面、空间深度与视差；屏幕输入能够反投影到正确 DOM 目标，并保持关键原生控件可用。

该子任务只交付本地交互实验室和可复用基础模块，不接入生产 Spatial Shell，也不适配任何正式平台面板。

## Parent and Dependency

- Parent: `.trellis/tasks/07-31-html-in-canvas-platform-ui`
- 本任务是其他 Spatial Desktop 子任务的前置依赖。
- 后续 Shell 子任务只有在本任务的曲面边缘命中、原生控件、资源生命周期和动效调度验收通过后才能开始实现。

## Confirmed Facts

- HTML-in-Canvas 当前要求可绘制顶层元素是 `layoutsubtree` Canvas 的直接子元素。
- WebGL 路径提供 `texElementImage2D`；API 仍处于实验阶段并可能变化。
- 浏览器提供的 DOMMatrix 同步适用于平面变换，不能直接覆盖最终非线性曲面后处理；曲面交互必须由应用反投影。
- 官方 3D 示例没有提供完整的交互式曲面 HTML；输入投影是本项目必须自行验证的能力。
- 项目当前没有 platform-web GPU 渲染器；可参考但不能直接复用 play-frontend 的局部 WebGL 特效代码。
- `frontend-inspector-dom.ts` 已有浏览器事件激活顺序经验，但属于检查器领域；只有形成真实第二消费者后才能抽取低层事件帮助函数。
- 用户已确认首版只面向桌面 Chromium、鼠标或触控板、WebGL 和足够视口空间，不要求手机或窄屏 Spatial 实现。

## Requirements

- 建立一个仅本地开发可访问的 Spatial interaction lab，不向正式用户暴露，也不改变 RetroOS 入口。
- 建立框架无关的 Spatial Engine 模块边界，至少分离能力适配、HTML 元素纹理、场景、投影、输入、Shader、帧调度、指标和资源销毁。
- 所有 HTML-in-Canvas 非标准 API 调用必须集中在单一适配层；Vue 组件和领域面板不得直接调用实验 API。
- 实验室必须使用真实 Vue/HTML 控件作为 Canvas 直接子级来源，不得使用静态截图或伪造交互替代。
- WebGL 渲染必须呈现浅水平圆柱曲面、低畸变中央区、更强边缘曲率，以及至少背景/窗口/前景三个视差层。
- 背景必须成为独立于曲面桌面的空间环境，不能与 HTML 面板一起经过同一曲面变形；主体是可替换的静态媒体基底，特效层以被动漂移的稀疏 GPU 粒子和分层视差提供空间感，不加入持续追踪、排斥或尾迹等强指针交互，也不得以高密度网格或高对比装饰干扰内容。
- 背景渲染边界必须允许后续将基底替换为图片、动图或视频，而不改动曲面桌面、HTML 纹理、投影输入和资源生命周期模块；本子任务只需交付默认静态基底与粒子效果，不包含壁纸选择、上传、持久化或媒体库。
- 静态背景基底不得因为粒子动画而重复上传；未来的动态媒体必须通过独立的帧需求接入调度器，而不是让全部 HTML 纹理进入连续上传。
- Canvas 与输入捕获层必须覆盖完整视口；曲面桌面的安全边距由渲染场景定义，而不是通过缩小 Canvas/Input Plane 留出不可追踪区域。
- 指针离开曲面内容的可视安全区时不得立即让视差归中；只有浏览器窗口失焦、页面隐藏或明确的复位动作可以触发平滑归中。
- 调试指标、生命周期探针和错误诊断能力必须保留，但默认视觉模式不得常驻显示调试入口；本地开发通过快捷键或显式 URL 参数开启。
- 曲面效果必须通过 GPU 生成，而不是只用 CSS `border-radius`、2D skew 或静态背景模拟。
- 输入系统必须完成屏幕坐标到曲面/场景、窗口 UV、源 DOM 本地坐标和最终目标元素的可逆映射。
- 输入系统必须统一处理 hover、click、double click、context menu、pointer capture、drag、resize、wheel/scroll、focus 和 cancel；不得由每个控件自行修正坐标。
- 实验室必须覆盖按钮、链接、文本输入、textarea、checkbox、radio、range、原生 select、contenteditable、可滚动区域、拖动面和调整尺寸手柄。
- IME、文件输入和浏览器原生弹出层必须通过真实浏览器探针明确支持方式或记录受控的 native escape；不能静默失效。
- 键盘焦点和输入仍由源 DOM 管理；Tab、Enter、Space、Esc 和常用编辑键不应经过 GPU 伪造。
- Source DOM 必须保留可访问语义，不能为了方便命中而整体设为 `inert`。
- `paint`/`changedElements` 只标记必要纹理为 dirty；空闲时不得持续上传全部 HTML 纹理。
- 连续 rAF 只在镜头、视差、过渡、动画或 dirty 内容需要时运行；空闲态采用事件驱动渲染。
- 必须统一处理 DPR/纹理尺寸上限、ResizeObserver、WebGL context lost/restored、元素移除和纹理释放。
- 必须尊重 `prefers-reduced-motion`，并让降低动效后的最终视觉层级和交互结果保持一致。
- 必须提供开发期帧数、帧耗时、纹理上传次数、纹理数量和资源销毁指标，供后续 Shell/面板任务使用。
- 不得新增全局 store、后端接口、共享 contracts 或业务存储表。

## Acceptance Criteria

- [ ] interaction lab 在所需浏览器 Flag 开启时渲染真实 HTML 到可感知的浅圆柱曲面，并展示三层输入驱动视差。
- [ ] 中央、左右极限可视边缘的目标点击均命中视觉上对应的 DOM 控件，没有随曲率增加的系统性偏移。
- [ ] 曲面上的 hover、双击、右键、拖动、调整尺寸、滚轮与可滚动容器行为可验证且不会跳变。
- [ ] 按钮、链接、input、textarea、checkbox、radio、range、select 和 contenteditable 均完成真实状态变更与事件触发验证。
- [ ] Tab/Shift+Tab、Enter、Space、Esc、文本编辑和中文 IME 在曲面实验室中可用，焦点样式能被捕获并显示。
- [ ] 文件输入与浏览器原生弹出层有明确、可复现的处理路径；不支持的部分以显式 native escape 呈现。
- [ ] source DOM 仍可被辅助技术识别，键盘用户可以在不使用空间指针的情况下完成实验室操作。
- [ ] 单个元素变化只上传对应 dirty 纹理；空闲态不持续上传纹理或保持无意义的动画循环。
- [ ] DPR 1/2、1920×1080 和最低支持桌面视口下，曲面与命中映射保持正确。
- [ ] `prefers-reduced-motion` 下关闭或缩短镜头/视差动画，所有操作仍可完成。
- [ ] 全屏任意视口位置均可连续驱动视差，指针跨过曲面内容边缘不会产生突然归中；窗口失焦或页面隐藏后按动效偏好平滑或立即复位。
- [ ] 背景空间不随 HTML 曲面一起弯折；默认静态基底保持稳定，稀疏粒子通过不同深度/速度和轻量视差产生可感知纵深，中央内容区没有影响阅读的高对比网格、边框或粒子噪声。
- [ ] 背景基底与粒子特效拥有独立渲染/调度边界，替换静态基底不会改变曲面桌面或投影输入，粒子连续动画不会触发静态基底或 HTML 元素的重复上传。
- [ ] 默认视觉模式不显示调试按钮或抽屉，通过约定的本地快捷键或 URL 参数仍能完整打开诊断界面。
- [ ] context lost/restored、源元素增加/删除、最小化式纹理释放/恢复和组件卸载不会泄漏 GPU 资源或留下失效引用。
- [ ] 投影、逆投影、相交、窗口 UV 与吸附所需的纯数学函数有自动化单元测试，包含中心、边缘、越界和往返误差用例。
- [ ] `npm run build:web`、聚焦单元测试和 `git diff --check` 通过。
- [ ] RetroOS 默认入口和现有平台路由行为不受影响。

## Out of Scope

- UI 模式持久化、Spatial Shell、应用注册表和生产路由接入。
- 正式平台面板适配。
- 手机、窄屏、触摸优先或真实 XR 设备支持。
- WebGPU 后端。
- HTML-in-Canvas polyfill。
- 服务器图片代理或跨域媒体架构改造。
- 为了实验室效果引入完整 3D 引擎或大规模视觉资产。
- 壁纸选择器、用户上传、媒体存储、壁纸库和壁纸偏好持久化。
