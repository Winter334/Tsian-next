# 优化开局向导角色选择体验

## Goal

提升开局向导“选择本局角色”步骤的产品表达与视觉完成度：让玩家只看到有助于理解和做出选择的信息，并让两个角色类型选项具有更清晰的差异、层级和交互反馈。

## Background

- 此步骤是此前“访谈驱动开局建模”流程的一部分，当前提供“原著角色”和“原创角色”两个入口。
- 上一任务已经确认：玩家选择分支后立即进入同一个 Agent 访谈；角色类型是唯一的前置选择，内部建模里程碑不得重新变成可见步骤或表单。
- 现有页面文案混入了实现方式和开发决策，例如“具体人物、身份和本局偏好会在接下来的对话里逐步确认”“通过简短问答创建角色，不需要预先填写完整表单”。
- 当前选项卡片主要依赖细边框、编号、标题和说明文字，两个选项的视觉识别度及可选感不足。
- 用户认为“开发侧决策污染面向用户的文案”并非单点问题，需要形成可复用的项目规范。
- 权威实现位于 `apps/play-frontend-dev/src/components/setup/step2/OpeningBranchChoice.vue`；点击卡片会直接调用 `startOpeningInterview`，没有持久的中间选中态。
- 同屏底部主操作显示禁用态“选择上方角色类型”，与可直接点击的卡片重复；动作配置位于 `apps/play-frontend-dev/src/components/setup/SetupWizard.vue`。
- `MethodChoose.vue` 已建立更完整的卡片视觉语言，包括渐变暗底、内阴影、角标、hover 微光和入场动画，可作为一致性参考，但不要求复制其布局。
- 当前 `.trellis/spec/` 没有面向最终用户的产品文案指南；`guides/prompt-self-contained-and-tone.md` 只约束 AI-facing 内容，不能替代玩家 UI 文案规范。

## Requirements

### R1 面向玩家重写本步骤文案

- 标题、副标题、选项标题与说明都应从玩家当下的目标和体验出发。
- 不向玩家解释表单、问答流程、后续确认机制或其他开发侧实现决策。
- 两个选项应清楚表达体验差异，并避免承诺当前产品能力以外的行为。
- 文案采用普通系统界面的直接表达，不使用“承接命运”“闯入世界”等风格化包装。基准文案为：
  - 区域标签：“角色设置”
  - 标题：“选择角色类型”
  - 说明：“选择使用小说中的已有角色，或创建一个原创角色。”
  - 原著角色：“从小说已有角色中选择。”
  - 原创角色：“创建一个新的原创角色。”

### R2 美化角色类型选项卡片

- 提升选项的可识别性、视觉层级、可点击感和两个选项之间的差异化。
- 保持现有开局向导的整体美术气质及桌面端/窄屏适配。
- 视觉可以比文案更华丽，但控制在现有暗金体系内：允许层叠暗色渐变、标记字、装饰边角、细微高光和阴影，不引入插画、外部图片或新的视觉主题。
- 两张卡片保持同等视觉权重，差异来自“原 / 创”标记与功能性文字，不暗示某一选项更推荐。
- 补全默认、hover、键盘焦点和按下反馈；不为了视觉效果新增独立确认步骤或改变分支启动时机。
- 审查并移除与卡片直接选择行为重复的禁用操作提示，保留必要的返回能力。

### R3 建立面向用户文案规范

- 在 `.trellis/spec/guides/` 新增项目级玩家可见产品文案指南，约束 UI 文案不得混入开发决策、实现机制、内部流程解释和无助于玩家行动的技术术语。
- 规范应给出可执行的判断方法与正反例，便于后续开发和审查复用。
- 将指南加入 `.trellis/spec/guides/index.md`。
- 本次只用新规范审查并修正角色类型选择页及其同屏操作文案，不审计完整开局向导或全仓 UI；其他页面后续按实际发现的问题单独修正。

## Acceptance Criteria

- [x] 角色选择步骤不再出现表单、问答方式、后续确认机制等开发侧说明。
- [x] 玩家无需理解系统实现，即可区分“原著角色”和“原创角色”所代表的体验选择。
- [x] 页面使用已确认的直接、非风格化系统文案，且两张卡片没有推荐倾向。
- [x] 两张选项卡片在默认、悬停、键盘焦点及按下状态下均具有明确且协调的视觉反馈，点击后仍按现有流程直接进入访谈。
- [x] 页面包含桌面双列、窄屏单列及 reduced-motion 规则；最终视觉效果由用户在平台挂载态手动验收。
- [x] 分支选择页不再显示与卡片直接点击重复的禁用主操作提示，返回入口仍可正常使用。
- [x] 项目规范包含面向用户文案的受众边界、判断清单和正反例，并被相关 spec 索引收录。
- [x] 受本次范围覆盖的静态检查、构建、源码包生成与独立质量审查通过。

## Out of Scope

- 改变“原著角色 / 原创角色”两条业务路径及其数据模型。
- 重做整个开局向导的视觉系统。
- 审计或批量改写完整开局向导及项目其他 UI 文案。
