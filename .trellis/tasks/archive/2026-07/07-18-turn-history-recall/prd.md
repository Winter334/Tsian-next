# Turn 历史召回体系

## Goal

为当前沉浸阅读器卡建立一套轻量、可维护的历史正文召回体系，使正文 Agent 在长线游玩中能按需找回很久以前 turn 正文里的关键细节，而不是依赖压缩摘要、全文 RAG 或平台自动语义提取。

本任务只验证当前实际使用的卡片工作区与必要前端显示，不把玩法 schema 固化进内置模板或平台核心。

## Scope

### In scope

- 修改当前卡片工作区：`cards/沉浸阅读器.tsian-card/workspace`。
- 在回合后维护中由场记维护 turn 级召回元数据。
- 为正文 Agent 提供历史召回 Skill/脚本。
- 为角色实体支持极简人物履历 `history: Array<{ event: string }>`。
- 在 `apps/play-frontend-dev` 角色档案概况页显示人物履历。

### Out of scope

- 平台级 RAG 重构。
- embedding / vector search。
- 额外 turn sidecar index 文件或全局索引文件。
- 平台自动提取玩法语义元数据。
- 将人物履历设计成结构化检索索引。
- 同步更新内置模板 `apps/platform-web/src/storage/workspace-templates/`。
- 新增平台 DB 表或平台通用语义字段。

## Background / Decisions

- `save/history/turns/turn-NNNNNN.json` 是历史正文权威；turn 文件名和顶层 `turn` 已承载回合号，召回元数据不重复记录 turn。
- 平台不自动向 turn 添加玩法语义字段；平台不应耦合沉浸阅读器/novel AIRP 的历史召回 schema。
- 系统确定性自动提取的语义有限；turn 召回元数据由场记在回合后维护中负责。
- 当前需求不优先做 RAG。更适合通过精心设计的 turn metadata + 多字段联合检索实现。
- 正文 Agent 是主要消费者，用于召回当前上下文/人物履历提到但缺少详情的旧事件。
- 人物履历存于角色实体中，只记录会长期影响角色态度、关系、目标或创伤的重要经历；每条只保留 `event` 一个字段，时间可自然写入内容，不强制结构化。
- 人物履历不是检索索引，不写 turn、tags、eventKinds 等内部字段；它只是正文 Agent 发起历史召回的语义入口。
- turn 召回字段使用中文，作为游戏卡 schema 约定，方便玩家/卡作者扩展和修改。

## Requirements

### R1. Turn recall metadata

场记在回合后维护中为当回合 turn 写入卡片私有的召回元数据块，例如：

```json
{
  "meta": {
    "recall": {
      "schema": "沉浸阅读器.turn-recall.v1",
      "剧情坐标": 42,
      "时间": "翌日清晨",
      "涉及实体": ["character:沈璃", "item:碎玉簪"],
      "事件类型": ["冲突争执", "关系变化", "承诺亏欠"],
      "标签": ["失约", "解释", "拒绝", "碎玉簪", "关系转冷"],
      "摘要": "玩家解释昨夜失约，沈璃没有接受，并把碎玉簪推回桌上。"
    }
  }
}
```

Field requirements:

- `schema`：固定版本标识。
- `剧情坐标`：对应当前 `runtime.plotOrder`，用于剧情阶段过滤；可缺省但应尽量填写。
- `时间`：当前世界/剧情时间的可读文本，可缺省。
- `涉及实体`：实体 ID/ref 数组（如 `character:沈璃`、`item:碎玉簪`）；只记录未来召回此轮最有价值的实体，不记录所有出现实体；通常不写主角，除非检索目标确实是主角的重大选择、承诺、身份或伤害。
- `事件类型`：受控中文枚举，第一版采用：`对话交流`、`玩家选择`、`冲突争执`、`关系变化`、`承诺亏欠`、`秘密揭露`、`发现线索`、`物品变化`、`状态变化`、`场景变化`、`战斗危险`、`计划目标`、`交易谈判`、`亲密暧昧`、`伏笔回收`。
- `标签`：自由短词/短语，用于记录非实体检索线索、主题、承诺、误会、物件名、关键动作等；不要写文学化空泛词。
- `摘要`：一句客观剧情摘要，用于候选 turn 快速判断和文本匹配。

### R2. Field ownership and write path

- `meta.recall` 由场记回合后维护 Skill 写入。
- 提供便利脚本/工具帮助场记快速写入当回合 turn 文件，只改 `meta.recall`，不改历史正文 timeline。
- 工具应校验事件类型、实体 ref 格式、标签数量/长度、摘要非空等基础约束。
- 如果同一 turn 已有 recall metadata，场记可覆盖更新该 metadata，使其与维护后的判断一致。

### R3. Character history

角色实体可新增人物履历字段，用于记录对角色有长期影响的重要经历。

Suggested shape:

```json
{
  "history": [
    { "event": "翌日清晨，因玩家昨夜失约而拒绝接受解释，并把碎玉簪退回。" }
  ]
}
```

Requirements:

- 每条只包含 `event` 一个字段。
- 不强制单独 time 字段；时间尽量自然写入 `event` 文本。
- 不写 turn、标签、事件类型、内部索引字段。
- 只记录会长期影响角色态度、关系、目标、创伤、秘密、承诺、恩怨或重要物件绑定的事件。
- 不记录普通流水账。

### R4. History recall Skill for storyteller

正文 Agent 通过专用历史召回 Skill 使用检索能力。

Skill must teach the storyteller:

- 何时召回：当前剧情需要理解人物履历、旧承诺、旧冲突、旧物件、旧伏笔等上下文中只简述但缺少正文细节的事件。
- 如何构建检索语句：使用半结构化参数，而非纯自然语言或关键词堆砌。
- 如何填写 `涉及实体`：直接填实体 ID/ref；不知道实体 ID 的线索放入 `标签`，不要硬猜。
- 如何使用结果：把召回结果当旧情材料，不在正文中暴露检索过程；找不到时不要编造。

### R5. recall_turns tool/script

提供正文 Agent 可用的检索脚本/工具。输入维度全部可选，但至少提供一个有效条件：

```json
{
  "涉及实体": ["character:沈璃", "item:碎玉簪"],
  "事件类型": ["关系变化", "承诺亏欠"],
  "标签": ["失约", "拒绝接受解释", "把碎玉簪推回桌上"],
  "时间线索": "翌日清晨"
}
```

Tool behavior:

- 只读取 turn 文件的 `meta.recall` 做初筛，不把大量历史正文直接注入正文 Agent。
- 内置候选上限和过宽保护，正文 Agent 不需要填写 `limit`、`时间模式` 等搜索策略参数。
- 默认最近优先；不暴露抽象的 `时间模式` 参数。
- 对候选做打分并返回少量结果。
- 返回结果至少包含 turn、path、score、matched、时间、摘要、涉及实体、事件类型、标签；可包含必要正文片段。
- 空查询或条件过宽时返回可操作提示，要求补充实体、事件类型、标签或时间线索。

### R6. Scoring principle

打分遵循：越精确、越稀有、越难偶然命中的匹配，分越高；越宽泛、越高频、越容易命中的匹配，分越低。

Requirements:

- 单个高频实体命中是弱信号；多个实体联合命中是强信号。
- 事件类型是粗筛，单独命中不应过高，和实体/标签组合时更有价值。
- 标签完整命中高于短字符部分命中。
- 查询短语一字不差命中摘要，尤其是较长短语，应作为强信号。
- 摘要/标签/时间线索应支持部分匹配；匹配字符或短词越多分越高，但短字符零散命中需要限权。
- 可选：根据出现频次对高频实体、事件类型、标签降权。

### R7. Frontend display

- 角色档案概况页显示 `history`。
- 缺省或空数组时不显示该区块。
- 无效条目（非对象或 `event` 为空）不显示。
- 展示内容只显示 `event` 文本，不展示任何内部索引字段。

## Acceptance Criteria

- [ ] 场记回合后维护 Skill 明确包含 turn recall metadata 维护步骤，并说明字段纪律。
- [ ] 场记有脚本/工具能写入当回合 turn 的 `meta.recall`，并校验基础 schema。
- [ ] 角色实体 schema/说明支持极简 `history: Array<{ event: string }>`，并明确只记录长期影响事件。
- [ ] 正文 Agent 有历史召回 Skill，能指导其在需要旧事件细节时构建半结构化检索语句。
- [ ] `recall_turns` 检索工具/脚本支持 `涉及实体`、`事件类型`、`标签`、`时间线索` 的联合检索，并内置候选上限/过宽保护。
- [ ] 检索工具返回可直接供正文 Agent 判断的候选摘要和命中原因，不要求正文 Agent 自己遍历 turn 文件。
- [ ] 检索打分符合精确/稀有匹配高分、宽泛/高频匹配低分的原则。
- [ ] 角色档案概况页能展示人物履历 `history[].event`，无履历时不展示。
- [ ] 本功能不引入平台级 RAG 依赖，不新增平台通用语义字段，不把沉浸阅读器玩法 schema 硬编码进平台或内置模板。
