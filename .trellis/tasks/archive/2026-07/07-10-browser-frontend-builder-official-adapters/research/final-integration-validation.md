## Bug found during integration and fixed

The fixture exposed a runtime-only bug not caught by `npm run build:web`:

- JS `?url` asset imports exported strings like `"./badge-QLFWJTFS.svg?url"`.
- In packaged iframe DOM usage, the browser resolved this relative to `frontend/dist/index.html`, requesting `frontend/dist/badge-QLFWJTFS.svg?url` and producing a 404.
- Worker `?url` assets had a similar fragile relative URL shape.

Fix applied during this parent integration:

- `workspace-source-plugin.ts` now turns explicit `?url` imports into JS modules that internally import the asset through a private `?__tsian_url_asset` file-loader request, strip query/hash from the generated string, and export `new URL(cleanAssetUrl, import.meta.url).href`.
- `worker-source-plugin.ts` applies the same pattern for Worker graph `?url` imports.
- `worker-build/paths.ts` allows the private internal url-asset query to use the file loader.

Re-validation showed clean DOM URL:

```text
.../frontend/dist/assets/badge-QLFWJTFS.svg
```

and no repeated fixture 404.
