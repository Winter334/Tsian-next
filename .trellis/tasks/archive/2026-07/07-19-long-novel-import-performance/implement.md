# Implementation Plan

## 1. Preparation

- Confirm the task is still `planning` until this file and `design.md` are reviewed.
- Before editing code, load `trellis-before-dev` for the relevant specs.
- Treat `apps/play-frontend-dev` and `cards/沉浸阅读器.tsian-card/frontend` as mirrored frontend source surfaces unless the implementation confirms the card mirror is generated by a packaging step.
- Treat `apps/platform-web/src/storage/workspace-templates/**` and `cards/沉浸阅读器.tsian-card/workspace/**` as mirrored runtime template surfaces for shipped card scripts/docs.

## 2. Frontend source data model

- Update `apps/play-frontend-dev/src/lib/source.ts` types:
  - Add `SOURCE_SHARDS_ROOT`.
  - Add sharded chapter source types.
  - Keep legacy `path?: string` readable for runtime/formal-play compatibility.
  - Add `shards` to `BuiltSourceCorpus` and remove/avoid per-chapter `content` for new imports.
- Refactor pure text helpers so they can run in a Worker:
  - Keep normalization, chapter detection, pseudo chapter splitting, title inference pure.
  - Build sharded corpus with `version: 2` index and about 1MB shard target.
- Add a shared frontend reader helper for preview:
  - Reads `chapter.source.kind === "shard"` by reading the shard and slicing offsets.
  - Falls back to legacy `chapter.path`.
  - Uses an in-memory shard cache for repeated preview reads.

## 3. Web Worker import builder

- Add a Worker entry, e.g. `apps/play-frontend-dev/src/lib/source-import.worker.ts` or `src/workers/source-import.worker.ts`.
- Add a main-thread wrapper, e.g. `buildSourceCorpusInWorker(input, onProgress)`:
  - Static import syntax must follow platform support: `import WorkerCtor from "./source-import.worker?worker"`.
  - Worker posts progress phases and a final sharded corpus.
  - Worker errors are surfaced as user-visible import errors.
  - Terminate worker in success, failure, and cancellation/cleanup paths.
- Replace `buildSourceCorpus()` usage in `useSetupState.ts` with the async Worker wrapper.

## 4. Workspace writes and import progress

- Replace `writeCorpus()` with `writeShardedCorpus()`:
  - Write shard files under `save/source/shards/`.
  - Update `statusText` for `写入源文本 x/y…`.
  - Write `chapters.index.json` then `manifest.json` last.
- Do not add workspace batch write/delete APIs.
- Do not clean old source files.
- Ensure `initialize()` can read v2 chapter indexes and does not call `ensureChapterCharacters()` in a way that tries to read every chapter.

## 5. Setup UI progress and virtual list

- In `SetupWizard.vue`, destructure and render `statusText` in a subtle progress/status line while importing or whenever useful.
- In `SplitReview.vue`:
  - Change preview loading to pass the whole chapter object to `loadChapterPreview`.
  - Implement fixed-height virtual scrolling for the chapter list.
  - Limit/disable GSAP list animation for large chapter counts.
  - Preserve selected row styling and preview switching.

## 6. Runtime template source reader

- Update `OPENING_COMMON_JS` in `apps/platform-web/src/storage/workspace-templates/scripts/opening.ts`:
  - Normalize v2 shard-backed chapters and legacy v1 `path` chapters.
  - Add `sourceRefForChapter`, `readSourceChapter`, and per-invocation shard cache helpers.
- Update opening scripts:
  - `inspect_source_opening` reads via `readSourceChapter`.
  - `read_opening_slice` reads via `readSourceChapter` and returns `ref` metadata.
  - `commit_runtime_and_frontier` validates chapter `ref` for v2 with `path` fallback for legacy.
- Update frontier scripts in `apps/platform-web/src/storage/workspace-templates/scripts/frontier.ts`:
  - `read_frontier_window` reads via the common source reader and returns compact `ref` chapter metadata.
  - `commit_frontier_state` validates refs and legacy paths.
- Update skill markdown/action descriptions in `world-architect.ts` so Agents are not taught to depend on `sourceWindow.chapters[*].path` or `save/source/chapters/`.
- Update researcher guidance in `agents/researcher.ts` to describe source reading by chapter/window rather than hard-coded chapter files.

## 7. Runtime workspace docs and template versioning

## 10. Rollback Points

- Before replacing `buildSourceCorpus()` exports, ensure old pure helpers remain available or are copied into the Worker safely.
- If Worker integration breaks packaged frontend build, revert only the Worker wrapper to main-thread async facade while keeping the sharded data model tests/checks visible; do not reintroduce per-chapter writes as the final state.
- If runtime template scripts fail validation, keep frontend import sharding but block task completion until opening/frontier readers are fixed, because Agent flow depends on them.
