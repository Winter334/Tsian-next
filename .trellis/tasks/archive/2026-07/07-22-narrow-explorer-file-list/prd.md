# 窄屏资源管理器文件列表适配

## Goal

资源管理器在自身可用宽度不足时，将文件详情表格简化为名称单列，避免固定宽表格造成信息裁切；宽度充足时继续保留完整文件信息。

## Background

- 当前目录列表强制 `min-width: 720px`，并以名称、类型、大小、更新时间四个固定列展示。手机截图中只能看到名称列和部分类型列，其余内容被横向裁切。
- 用户认为类型、大小和更新时间在窄屏下不是重要信息，也认为把它们放到文件名下方的双行布局不够美观，因此选择直接省略次要列。
- 资源管理器可在桌面窗口中调整宽度，适配应依据组件自身可用空间，而不是设备或浏览器 viewport。

## Requirements

- 资源管理器目录列表在自身宽度较窄时只显示名称列，隐藏类型、大小和更新时间的表头及内容。
- 窄宽度下移除目录列表的固定最小宽度，名称列使用全部可用空间，不产生列表自身的横向裁切。
- 宽度充足时继续显示名称、类型、大小、更新时间四列，保持现有桌面信息密度。
- 文件与目录继续通过现有图标区分；不为被省略的信息增加第二行、tooltip、详情面板或其他替代入口。
- 保持选择、打开、重命名、右键菜单、复制、剪切、粘贴、删除和键盘快捷键等现有行为不变。
- 仅调整正在浏览目录时的文件列表，不改工作区根卡片、搜索结果、工具栏和状态栏。
- 不引入全局移动端布局或全局断点；响应规则局限在资源管理器文件列表。

## Acceptance Criteria

- [x] 在用户截图对应的窄宽度下，文件列表只显示名称表头和文件/目录名称，不再显示被截断的类型文本。
- [x] 窄宽度下列表完整占据可用空间，没有由原 `720px` 最小宽度造成的横向裁切。
- [x] 文件名过长时仍使用单行截断，重命名输入框可正常使用。
- [x] 宽度充足时四个原有列及其内容全部保留。
- [x] 列表切换由资源管理器自身可用宽度决定，桌面端缩窄窗口时同样生效。
- [x] 现有文件选择、打开、重命名和上下文菜单等交互无回归。
- [x] `npm run build:web` 和 `git diff --check` 通过。

## Out of Scope

- 改变文件元数据来源或格式。
- 为窄屏隐藏的信息新增查看入口。
- 调整搜索结果、根目录选择、工具栏、路径导航或状态栏。
- 全站视觉风格切换或公共 UI 框架建设。
