# 窄屏双列视图适配

## Goal

一次性修复工作室、桌面助手和创意工坊在自身可用宽度较窄时，辅助栏挤占主要内容空间的问题；根据三个辅助栏各自的产品职责采用不同的紧凑呈现，并保持宽度充足时的现有双列布局。

## Background

- 工作室当前仅在 `xl` 以上显示 Agent 列表与详情双列；窄宽度下两者上下堆叠，Agent 列表占据大量垂直空间，编辑详情被压缩。
- 桌面助手始终使用固定 `220px + 主聊天区` 双列；手机宽度下主聊天区只剩极少空间，消息、标题和输入区严重裁切。
- 创意工坊仅在 `lg` 以上显示资源类型侧栏与内容双列；窄宽度下完整类型侧栏堆叠在内容上方，再叠加工具栏换行，首屏主要被筛选控件占据。
- 三个页面形式相似但辅助栏职责不同：工作室是对象选择、助手是持续会话管理、创意工坊是列表筛选。因此本任务不预先抽取通用 `ResponsiveSplitView`，而是在各页面内做最小、职责匹配的适配。
- 用户要求三处一次性完成，最后统一进行手机手动验收。

## Requirements

### 工作室

- 宽度充足时保留现有 Agent 侧栏与详情双列布局。
- 窄宽度下不再上下堆叠完整 Agent 列表，改用紧凑 Agent 选择器，并保留打开当前 Agent 目录的入口。
- 当前 Agent 的标签页和详情占据主体剩余空间。
- Agent 切换继续复用现有选择和上下文加载逻辑；不得改变 Agent 配置、Skill、消息序列或运行配置的数据行为。

### 桌面助手

- 宽度充足时保留固定会话侧栏和聊天主区双列布局。
- 窄宽度下聊天区占据完整主体宽度，会话侧栏改为从左侧覆盖显示的抽屉。
- 聊天标题区提供清晰的“会话”入口；点击遮罩或选择会话后关闭抽屉。
- 抽屉中继续支持创建、选择、重命名和删除会话，并显示后台生成状态。
- 抽屉切换不得卸载聊天主区，不得中断前台或后台流式回复，不得破坏消息滚动位置、输入草稿或当前会话状态。
- 若聊天区恢复完整宽度后输入区仍能正常使用，本任务不额外重构 Composer。

### 创意工坊

- 宽度充足时保留现有资源类型侧栏与内容双列布局。
- 窄宽度列表页将资源类型侧栏收为紧凑筛选栏：资源类型使用紧凑选择控件并保留计数，全部资源/我的上传保留独立切换入口。
- 窄宽度下整理顶部工具栏：上传与排序同组，搜索和 Tag 输入获得明确的整行宽度，避免当前参差堆叠。
- 详情页和上传页在窄宽度下不显示资源类型紧凑筛选栏；返回入口与现有导航状态保持不变。
- 类型、范围、排序、搜索和 Tag 继续复用现有状态与刷新逻辑。

### Shared Constraints

- 三个视图均应依据自身可用宽度切换，而不是按设备类型或全局 viewport 判断。
- 保持现有 Retro OS 视觉方向；本任务不进行整体美术风格切换。
- 不抽取通用双列布局组件，不引入全局移动端壳层或全局响应式状态管理。
- 不改变后端、存储、运行时或 contracts。

## Acceptance Criteria

- [x] 工作室窄宽度下不再显示占据大量高度的完整 Agent 列表，当前 Agent 详情拥有主体空间，且可切换 Agent、打开目录。
- [x] 工作室宽度充足时原双列布局与功能无明显回归。
- [x] 桌面助手窄宽度下聊天区完整可用，不再被固定 220px 会话栏挤压。
- [x] 桌面助手会话抽屉可打开、关闭、创建/选择/重命名/删除会话，后台生成状态仍可见。
- [x] 打开或关闭助手抽屉不会中断回复、清空输入、重置消息或导致当前会话错误切换。
- [x] 桌面助手宽度充足时原固定侧栏布局无明显回归。
- [x] 创意工坊窄宽度列表页以紧凑方式展示资源类型与范围筛选，资源内容更早进入可视区域。
- [x] 创意工坊窄宽度工具栏排列规整，搜索和 Tag 输入不发生横向裁切。
- [x] 创意工坊详情页与上传页在窄宽度下不显示资源类型紧凑筛选栏，现有返回和操作流程可用。
- [x] 创意工坊宽度充足时原侧栏与工具栏行为无明显回归。
- [x] 三处适配由各视图自身宽度触发，没有新增通用双列组件或全局移动端布局。
- [x] `npm run build:web` 和 `git diff --check` 通过。

## Out of Scope

- 重做三个页面的整体视觉风格。
- 抽取通用响应式双列组件或全局设计系统。
- 重构助手消息、会话持久化、Agent Studio 数据或创意工坊 API。
- 对尚未确认有问题的内部表单、消息内容、编辑器和资源卡片进行全面移动端重构。
