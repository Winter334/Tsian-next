# 窄屏任务栏适配

## Goal

修复平台底部任务栏在手机等窄屏视口中横向内容超出、右侧区域被裁切的问题，同时保留现有 Retro OS 桌面壳层和已经得到用户认可的移动端操作方式。

## Background

- 用户已在真实手机上验证当前平台，认为整体布局和操作手感良好；本任务不是重做移动端壳层，而是修复一个明确的局部显示问题。
- 用户提供的截图中，底部任务栏从左到右包含开始/品牌入口、通知、连接/数量、账户和时钟等区域；视口无法完整容纳全部内容，最右侧时钟被裁切。
- 现有任务栏允许整栏横向滚动，但中部窗口任务列表也已经是独立的可收缩、可横向滚动区域。窄屏下“公告”“在线”和未登录时的“登录”会隐藏，登录后的用户名与“TSian”品牌文字仍保持显示，导致固定区域总宽度继续超过视口。
- 本次改造是渐进式 UI 演进的第一个切片：在解决窄屏问题时可顺带改善局部视觉，但不预先抽象完整视觉变量层或 UI 框架。只有被当前改造验证为稳定、且确有复用价值的样式才应收敛。

## Requirements

- 保持现有 Retro OS 桌面、窗口和任务栏交互模型，不引入独立移动端壳层。
- 窄屏下将开始入口的“TSian”文字和已登录账户的用户名收成图标表达；按钮保留原有语义、提示和点击行为。
- 公告入口、在线人数、账户入口与时间应继续直接可见；打开窗口后，中部窗口任务列表使用剩余空间并保持独立横向滚动。
- 窄屏任务栏自身不得通过整栏横向滚动来隐藏固定入口；桌面宽屏下继续保持现有完整文字布局。
- 适配不得破坏桌面宽屏下现有任务栏布局和操作。
- 不在本任务中预建完整 token、主题或公共组件体系；局部美化和样式收敛以解决当前问题所需为限。
- 改动应覆盖任务栏自身；除非定位证明确有必要，不扩大到桌面图标、窗口内容或其他页面。

## Acceptance Criteria

- [x] 在用户截图对应的窄屏宽度下，任务栏完整位于视口内，最右侧时间不再被裁切。
- [x] 窄屏下开始入口和账户入口显示为可辨认的图标按钮，公告、在线人数和时间保持直接可见。
- [x] 存在已打开窗口时，中部窗口任务列表占用剩余宽度并可独立横向滚动，不把右侧固定入口挤出视口。
- [x] 任务栏没有引起页面级横向溢出，且不会遮挡或挤出自身边界。
- [x] 桌面宽屏下继续显示“TSian”和账户名，任务栏布局与交互无明显回归。
- [x] 实现继续沿用现有视觉方向；没有为了本次修复引入完整移动端布局或大范围 UI 重构。
- [x] `npm run build:web` 和 `git diff --check` 通过。

## Out of Scope

- 重做移动端桌面或窗口管理交互。
- 全站视觉风格切换。
- 一次性抽取全局设计 token 或完整 UI 组件库。
- 修复任务栏之外尚未明确提出的移动端问题。
