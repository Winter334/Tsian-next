# 开局建模提示词重构与属性刻度规范

## Goal

把世界架构师《开局建模》的**知识**与**流程**分离：新增 workspace 契约与通用属性刻度规范两份参考文档，`SKILL.md` 瘦身为「流程 + 关卡」，并修复一次真实开局中暴露的过期标记、路径盲搜、关系分片缺口与属性刻度失准。

目标不是重写开局流程，而是让同一份知识只有一个出处，且世界架构师能读到它。

## Background

证据来自 2026-08-29 导入《逆天邪神》的一次真实开局（请求日志 `tmp/请求-开局建模.txt`）。第 5 阶段单次 invocation 用了 15 个模型轮次，其中 6~7 轮是纯路径考古；落盘资料存在关系分片缺失与属性刻度失准。

根因收敛为两条：

1. **世界架构师没有 workspace 契约文档。** 场记的《回合后维护》有 `workspace-map.md`（ref→路径表、双向关系规则、字段口径），世界架构师没有对应物，于是路径靠猜、关系写漏、属性刻度各猜各的。
2. **调用方复述了被调用方的输出契约。** `SKILL.md` 复述了 storyteller 的选项格式与字数，改版后没同步，产生漂移。

## Requirements

### R1 新增 workspace 契约文档

- 位置需让《开局建模》与《frontier推进》两个 skill 共用。
- 至少覆盖：ref→文件路径对照表、实体/场景/关系各自的权威归属与字段口径、关系分片完整性规则（D4）、「切入点时刻快照」规则（D6）。
- 与场记 `回合后维护/workspace-map.md` 保持事实一致；同一事实不得给出两种说法。

### R2 新增通用属性刻度规范文档

必须覆盖任意世界观（仙侠 / 西幻 / 都市 / 权谋 / 无力量体系），不得写死某一套境界名。规范需包含：

- **绝对锚点**：普通成年人基础六维为 5。
- **维度分类**：成长维（随力量体系暴涨）/ 天赋维（先天素质）/ 混合维。天赋维在任何世界观下恒定 1-15，使跨等级角色仍可比较。
- **档位曲线**：给出 3 档（平缓 3-5x / 中等 20-50x / 陡峭 1000x+）供选择，而非给死数值表。
- **可执行流程**：读原文判断力量体系陡峭度 → 选档 → 把本书等级阶梯映射成数值区间 → 写入 `save/schema/current.md`。
- **维度可变性护栏**：4-8 维；每维标注类别；至少 1 个成长维 + 至少 2 个天赋维；开局落盘后不再改名（存档兼容）。
- **自检判据**：同体系内等级不同的两个角色，成长维必须有可见差值。

### R3 SKILL.md 瘦身为流程 + 关卡

- 移除对 storyteller 输出契约的复述（选项标记、字数、选项条数），改为「以 storyteller 自身输出格式为准」（D1）。
- schema 与路径知识移交 R1/R2 文档，SKILL 仅在对应阶段引用。
- §5 核对改为显式清单，必须写出逐条判定结果后方可 publish（D3）。
- 修正 §3 的误导措辞（D2）。

### R4 工作笔记模板补全

补「已落盘路径」「世界观口径与刻度」「切入点对应 source 锚点」三栏；要求每次 commit 成功后把返回的 `writes` 路径记入笔记（D7）。

### R5 plotOrder 正确性

`commit-opening-state.js` 增加一个可选的切入点锚点输入字段，缺省回退到现有 `timeline[0].order` 行为；提示词侧同时教架构师传该字段。脚本兜底，提示词驱动。

### R6 `save/schema/current.md` 升级为「本存档口径卡」

平台模板 `files.ts` 中的 `current.md` 内容改为带空槽位的中文骨架，题材中性、不绑定任何小说。槽位至少含：

- 力量体系阶梯（本书等级序列，低→高；无力量体系时显式写「无」）
- 属性档位与区间映射（选用哪档曲线、各阶梯对应的成长维区间）
- 六维定义（名称、数量、每维所属类别）
- 世界观术语与称呼约定（可选）

`SKILL.md` 在实体阶段前要求架构师填写该文件。**不改动模板文件的任何加载逻辑，只改模板文本内容。**

### R7 schema guide 去表化

移除 `novel-airp-schema-guide.md` 中那张仙侠专用境界数值表，改为「字段形状 + 普通成年人=5 锚点 + 指向属性刻度规范文档」的指针，使刻度只有单一出处。

## 决策记录

2026-08-30 与用户确认：

| 决策点 | 结论 |
|---|---|
| `current.md` 改法 | 平台模板加空槽位（题材中性、英改中），配合 SKILL 要求填写 |
| plotOrder 修法 | 脚本加可选参数 + 提示词教它传，脚本缺省兜底 |
| 阶段合并 | 合并实体 + 场景/关系两阶段；状态与发布保持独立。continue 从 3 次降到 2 次 |
| 旧境界表 | 删表换指针，刻度只留新文档一处出处 |

## Constraints

- **不得修改 `commit-opening-*.js` 的锁定逻辑**（`OPENING_ENTITIES_LOCKED` / `OPENING_GRAPH_LOCKED` / `openingAssertPathSet`）。那是防止开局资料被覆盖的安全机制。
- **分发模型**：卡内容随卡打包上传创意工坊，改完即生效，新增卡内文件无需登记平台模板数组；`save/**` 仍由平台自动创建，故 `files.ts` 中 `save/schema/current.md` 的模板文本是本任务唯一必须改的平台代码，且只改文本、不碰加载与写入逻辑。
- **测试立场**：测试为开发让路。逐字锁措辞、范围过窄的断言挡路时直接改或删；只保留断真实行为契约的用例。不得为了让测试变绿而扭曲提示词写法。
- `commit-opening-state.js` 的改动限于新增可选输入字段与其缺省回退，不得改变既有校验强度。
- 阶段合并**只改提示词**：脚本本身已允许单次 invocation 连做多个 action，本次实际运行也是如此。
- 属性规范不得写死任何一部小说的境界名。
- 语言边界遵循 `novel-airp-schema-guide.md`：JSON 字段与枚举用英文，说明与玩家可见文本用中文。
