## 体验目标

玩法从“提取小说设定后自由拼接新剧情”，转为“以原著世界、人物与剧情为默认依据，玩家行为能够产生自然分歧的互动改编”。

- 正文创作者能够阅读相关原文和原剧情，继承原著人物表现、因果与文风，而不只有实体摘要。
- 未被本局变化影响的部分自然沿用原著；受到玩家行为影响的部分顺着本局新因果继续，不强制拉回原著。
- 作者知道原剧情，不等于人物知道未来。人物认知、叙述视角和揭示时机主要用提示词约束，不再通过让创作者缺少必要原文来防剧透。不承诺提示词能保证零泄漏。
- 先实现原著阅读与剧情推进能力，主推原著文风；不同时大改或新建整套 Agent 预设系统。

## 已确认的职责

### 正文 Agent：创作与推进

消费原著、玩家设定/输入、已落定本局历史与相关资料，负责续写和剧情推进。剧情相关访谈（角色、切入点、介入方式）随创作职责收敛到正文 Agent，保留现有界面的玩家方案确认能力。

提供专用原著阅读/定位能力，优先复用现有分片读取。程序处理路径、分片和必要的读取状态；Agent 选择语义上需要的内容，不人工运行旧 frontier 流程。

作者可以按需阅读前后文；不每轮注入整本小说，不先生成全书实体库。阅读位置是检索书签，不是剧情锁或强制进度。必要时可以保留简短、可变的创作笔记；不是每轮必写大纲、额外规划调用或前端可见的未来事实。

### 世界架构师：世界/schema 适配

根据小说世界观定义必要概念、属性含义、力量口径及展示规则，通过专用语义工具完成卡属 schema/规则适配。它不再预建整套人物、物件、场景和关系库，不规划正文、审稿、调用写手或逐轮维护。

“维护 schema”不意味着恢复 Agent 手写路径/原始 JSON。程序继续生成确定性存储/可渲染结构；沿用现有主要资料类别和可用展示能力，不建设万能 schema DSL。也不为可能出现的新概念每回合固定调用架构师。

### 场记：本局事实的整理者

依据已落定正文、玩家确认的必要前提及已有资料，建立/更新实体、关系、场景、状态和重要历史记录。实体是本局已确认事实的可查询归纳，不再是创作必须预先具备的清单。

“来自历史”不要求事实只能出现在当轮台词中：明确继承的前史、已确认玩家身份和开局前提可以作为初始依据；角色猜测/台词不自动成为客观事实。未出场对象没有实体文件，不代表它在世界中不存在。

不为比较差异给场记注入原著或要求它阅读原著。**本轮明确取消原著偏离识别与展示**，也不把差异报告转交给正文 Agent。

### 程序

继续承担标识、引用、文件/渲染包装、确定性计算、固定调用编排、原子提交与恢复。通用注入器保持 schema 无关；卡属材料准备和规则翻译留在卡文件、专用工具和真实卡前端。

## 本轮配套范围

1. **提示词、Skill、工具、注入材料和动态生成点一起更新。**保留直接可用的酒馆移植模块；与原著或新职责冲突、需要大量适配的模块可停用/舍弃，不为它们增加兼容机制。必要输出格式与行动选项机制仍保留。
2. **不设计“继续”的特殊机制。**用户认为行动选项和已有上下文续写能力足够；即使输入“继续”，也自然延续当前故事。不要添加强制回原著、专门处理分支或额外的重大决定确认流程。
3. **名称查询与创建候选检查。**保留稳定内部 ID，不要求 ID 与名称绑定。Agent 通过名称/别名、简介等确认对象；创建前程序检查已有候选，存在疑似对象时返回候选供判断，不默默创建重复对象，也不按同名自动合并或覆盖。检索截断不能作为“不存在”的证据。无需 RAG 重构。
4. **历史时间线。**只展示本局已经发生的重要节点，优先复用现有摘要/记录；不要求每回合制造节点或另写一份完整剧情摘要。解除界面对 frontier 的依赖，缺少旧文件不能再显示损坏/不可读。不是原著未来图、写手大纲展示或偏离对照图。
5. **退出旧 frontier 的剩余耦合。**包括原作文风学习的 sourceWindow 前置条件、旧推进/对齐提示、相关展示和数据消费者。不复活旧系统，也不改名重建一套等价机制。plotOrder 曾包含语义判断：如随旧功能退出而退役，是因为职责改变，不是因为数值字段都是机械字段。
6. **保留有效一致性能力。**初始资料改为正文后建立时，联动开局材料、场记 turn 0 初始化、确认/发布/完成条件、首个正式回合和 checkpoint。维护失败不重写正文，刷新不静默调用 AI；不能把旧“已提交完整模型”作为新流水线前提。

## 明确不做

- 通用预设系统重构、全书预建模、完整剧情树、每轮强制显式规划或额外规划 Agent。
- 原著偏离/并回/对齐识别、差异报告、评分、双轨对照图、为此给场记补原文；不能把这些换成正文 Agent 的新负担。
- 逐角色知识数据库、复杂防剧透访问控制、旧 frontier 兼容框架。
- RAG：当前废弃但保留，留待后续重构，不顺带清理或增强。
- 资料分类整体重做（records/seeds/recall 等暂保留）、恢复废弃平台模板或卡内旧前端副本。
- 旧卡/旧存档迁移框架。测试阶段只有一张官方卡，采用简单逻辑和新存档测试。
- 自动 commit/push、真实/付费 AI 本地验收。
