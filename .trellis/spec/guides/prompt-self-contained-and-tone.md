# 提示词自包含与口吻指南

> **Purpose**: 写 Skill / AGENT.md / 工具 description 这类 AI-facing 提示词时，避免两类常见错误：把开发侧因果解释当指令写进去；默认 Agent 知道本上下文之外的概念。

---

## 两类错误

### 一、面向开发者的口吻污染

写进去的不是 Agent 该执行的动作，而是开发侧的因果解释：

- "为什么这么做"（理由、设计动机）
- "后续谁来处理"（其他 Skill / 阶段的兜底）
- "两个阶段怎么衔接"（流程侧的因果链）

Agent 只需要"做什么、怎么判断、写成什么样"。理由解释删掉。理由本身若是 Agent 做判断的依据（如"当 X 时选 Y，因为 Z"中的 Z 决定边界），保留 Z；纯粹讲给开发者听的因果链删掉。

**反例**：

> 实体只反映开局锚点这一刻为真的事实——它们在开局时刻还没发生，frontier 推进时会按对应 source 锚点抽取写入。

"frontier 推进时会按对应 source 锚点抽取写入" 是开发侧兜底解释，对 Agent 行为没有指导意义，Agent 也不需要知道后续流程。删掉即可：

> 实体只反映开局锚点这一刻为真的事实——它们在开局时刻还没发生。

### 二、不自包含

Skill 按需注入，Agent 执行某个 Skill 时只看得到**这份 SKILL.md 直接提供的内容**。其他内容都不是默认已知的：

- 同目录参考文档：属于本 skill，Agent 可以读，但 SKILL.md 必须指明去读，不能默认 Agent 已经看过
- 其他 Skill / 其他 docs / Agent 入口 contextPath：不能当已知
- `{{file:...}}` 这类宏是 Agent 入口 contextPath 的机制，不是 Skill 机制，不能假设 SKILL.md 里能用

引用到 SKILL.md 里的字段、流程、术语，必须在**本 Skill 内**建立已知性。

---

## 跨 Skill 概念的处理原则

引用到 SKILL.md 里的概念，必须在本 Skill 内建立已知性。两种处理方式，按情况选：

### 重建

把概念用本 Skill 自己的说法重写一遍。

**适用**：

- 概念在本 Skill 里只用到一小部分、表达方式需要贴合本 Skill 的语境
- 概念是另一 Skill 的内部流程细节，整份纳入反而拖累本 Skill

**要求**：

- 忠实于原义，不要走样
- 只覆盖本 Skill 用到的部分，不必覆盖原概念全貌

### 纳入

把承载该概念的文档作为本 Skill 的参考文档，放在本 Skill 目录下，SKILL.md 里指明去读。

**适用**：

- 概念体量较大、自成体系，重建会双份维护且易走样
- 概念被多个 Skill 共用，统一来源比各自重建更稳定

**要求**：

- 纳入不是把全文塞进 SKILL.md，而是把文档放进 skill 目录，由 SKILL.md 指明"遇到 X 情况去读 docs/xxx"

### 判据

**重建成本 vs 纳入成本**。

- 重建成本低、概念在本 Skill 用得浅 → 重建
- 重建要写一大段、还会跟其他 Skill 共用 → 纳入

## 自查清单

写完提示词读一遍，假装只看过当前这份 SKILL.md：

- [ ] 提到的字段、流程、术语，在 SKILL.md 里出现过吗？
- [ ] 同目录参考文档里的内容，SKILL.md 有指引 Agent 去读吗？
- [ ] 每句话是"做什么 / 怎么判断 / 写成什么样"，还是"为什么"？
- [ ] 有没有一句话让我想问"那是什么""这个哪来的"——有就按重建或纳入处理
- [ ] 如果选了重建：重建版忠实于原义吗？只覆盖本 Skill 用到的部分吗？
- [ ] 如果选了纳入：参考文档放进 skill 目录了吗？SKILL.md 指明去读了吗？

## 复现案例（2026-07-19，开局建模与游玩设定衔接）

**症状**：开局建模阶段读取多章开局素材后写实体，可能把开局锚点之后章节的事件写进 `history` / `status` / `goals` / relationships；游玩设定阶段定下切入点后没回炉修正，导致 storyteller 读主角实体时把未发生事件当作已发生。

**修法**：

- 开局建模 SKILL spoiler-safe 加判据：实体只反映开局锚点这一刻为真的事实，窗口里开局锚点之后章节的事件不写入。开局锚点 = `timeline` 第一个锚点 = `sourceWindow.startIndex` 这一章。
- 游玩设定 SKILL 落盘流程加一步：定下切入点后，把主角和开局出场角色实体调整到切入点这一刻的状态，切入点之后的事件从 entity 拿掉。

**过程中犯的两类错误**：

1. spoiler-safe 初稿写"frontier 推进时会按对应 source 锚点抽取写入"——开发侧兜底解释，Agent 不需要知道，删掉。
2. 游玩设定 SKILL 初稿用"窗口里切入点之前/之后"下指令——但"窗口" `sourceWindow` 字段在这个 Skill 上下文里没出现过，Agent 看不到。改用本 Skill 已建立的"已读开局素材""切入点""后续章节"重写。

**字段名交叉确认**：开局建模 SKILL 用 `sourceWindow.startIndex`（入参阶段字段名），schema reference 和 frontier 推进用 `sourceWindow.start`（落盘后字段名），两份文档各自正确，不是冲突。开局建模 SKILL 内部一处 `sourceWindow.start`（重试策略段）引用的是入参，应是 `sourceWindow.startIndex`，修正。
